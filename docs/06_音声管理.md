# 06_音声管理と聴取状態

## この文書の目的
MAGNOLIA において、通信音声の聴取状態はゲームプレイの中心にあります。
この文書では「ノイズ強度」「聴取状態の記録」「被弾の影響」「演出への変換」を担う仕組みを定義します。

データ型の全文は `05_データ構造` に記載しています。この文書は設計の意図と動作フローを補足します。

---

## 設計原則

- 自機には HP がなく、死亡もない
- 被弾は「聴取状態の悪化」として現れ、ゲームオーバーにはならない
- 「失敗はない、ただし聴けなかった部分が増える」

---

## ノイズ強度（NoiseState）

バトル中の聴取状態は `NoiseState` として管理します。これはランタイム状態であり、IndexedDB には保存しません。

```ts
export type NoiseState = {
  noiseLevel: number          // 現在のノイズ強度 (0.0 ~ 1.0)
  decayRate: number           // 1秒あたりの自然減衰量
  hearingThreshold: number    // これ以上のとき通信が聴こえない (例: 0.7)
  invincibleUntilMs: number   // この時刻まで被弾判定なし（無敵時間管理）
}
```

`noiseLevel` の意味:

| 範囲 | 状態 | 記録 |
|---|---|---|
| `0.0` | 完全クリア | `heardRanges` に積算 |
| `0.0 ~ hearingThreshold` | 軽微なノイズあり | `heardRanges` に積算 |
| `hearingThreshold ~ 1.0` | 聴取不可 | `damageRanges` に積算 |
| `1.0` | 完全遮断 | `damageRanges` に積算 |

`hearingThreshold` の解決順:
1. `MissionMaster.hearingThresholdOverride` が設定されていればそちらを使う（ボス戦は厳しく、チュートリアルは易しく、など）
2. なければ `PlayerShipSpec.hearingThreshold` を使う
3. 全体難易度 `Difficulty` の修飾子がさらに加算される（`06_音声管理` 参照）

## 被弾によるノイズ発生

敵弾が自機に当たると `ProjectileSpec.noiseDamage` だけ `noiseLevel` が上昇します。
磁気災害に接触した場合も、`BattlefieldHazardSpec.noiseDamage` を `tickIntervalMs` ごとに同様に加算します。

```
noiseLevel += projectile.noiseDamage
noiseLevel = clamp(noiseLevel, 0.0, 1.0)
```

敵機との直接接触（体当たり）は `EnemyArchetype.collisionDamage` を `noiseDamage` として同様に扱います。

---

## 無敵時間

被弾や近接攻撃の直後は `invincibleUntilMs` が設定され、その間は被弾判定をスキップします。

| 種別 | パラメータ |
|---|---|
| 被弾後の無敵 | `PlayerShipSpec.invincibilityMs` |
| 近接攻撃後の無敵 | `PlayerShipSpec.meleeInvincibilityMs` |

`stepBattle` は各フレームの先頭で `invincibleUntilMs > currentTimeMs` を確認し、有効な場合は衝突判定を行いません。

---

## 聴取状態の記録フロー

`stepBattle` の各フレームで以下を行います。

1. `noiseLevel` を `decayRate * dtMs / 1000` だけ自然減衰させる
2. 衝突判定を行い、被弾した場合は `noiseDamage` を加算し、無敵時間を設定する
3. 現在の `noiseLevel` と `hearingThreshold` を比較する
4. クリアなら現在のフレーム時間帯を `heardRanges` に積算、ノイズ超過なら `damageRanges` に積算する

`heardRanges` の累積が `archiveRestorationRate`（本文開放率）に直結します。

## 演出への変換

`stepBattle` は被弾時に `PresentationRequest` を返します。

```ts
export type HitPresentationRequest = {
  requestId: string
  cueId: "battle.player.hit"
  channel: "battle"
  blocking: false
  noiseLevel: number   // 被弾後のノイズ強度（演出強度の調整に使用）
  worldPosition: Vector2    // 被弾位置
}

export type NoisePeakPresentationRequest = {
  requestId: string
  cueId: "battle.noise.peak"
  channel: "battle"
  blocking: false
}

export type NoiseClearPresentationRequest = {
  requestId: string
  cueId: "battle.noise.clear"
  channel: "battle"
  blocking: false
}
```

演出実装（Claude Code 担当）はこれらの request を受けて以下を行います：

- `battle.player.hit`: 画面端の歪み・フラッシュ、通信音声への砂嵐 SE ミックス
- `battle.noise.peak`: noiseLevel が閾値を超えた瞬間の音声途切れ演出
- `battle.noise.clear`: 閾値以下に戻った瞬間の音声復帰演出
- `noiseLevel` に応じて、音声の再生速度揺れ・フィルタ強度を連続的に変化させる

## 補助装備のトリガ

被弾を `subsystem` スロット装備の発動条件として使えます。

現段階では `EffectSpec.hookKind` と `subsystemHooks` を使って評価します。

- `hookKind: "onPlayerHit"`
  - 被弾時に呼びます。例: ノイズ軽減、緊急防御
- `hookKind: "onBattleStep"`
  - 戦闘中の時間経過ごとに呼びます。例: 解析率の継続上昇
- `hookKind: "onExploreStep"`
  - 探索中の視界補助やマップ補助に使います

`runSubsystemHooks(...)` は `analysisDelta` `noiseDelta` `effectRequests` を返し、戦闘ロジック側がその結果を適用します。

## PresentationCue 追加分

以下の cue ID は `05_データ構造` の `PresentationCueSpec` と `PresentationRequest` に追加します：

| cueId | channel | 内容 |
|---|---|---|
| `battle.player.hit` | battle | 被弾エフェクト＋ノイズ音 |
| `battle.noise.peak` | battle | 聴取不可状態に突入した瞬間の演出 |
| `battle.noise.clear` | battle | 聴取可能状態に復帰した瞬間の演出 |
| `battle.invincible.start` | battle | 無敵時間開始の視覚フィードバック |

## 音声再生のタイミング

ミッション中の通信音声は `MissionMaster.audioStartDelayMs` の経過後に再生を開始します。

- 導入余白 (intro): `audioStartDelayMs` の間は音声なし。接続演出や戦場への慣熟時間として機能する
- 再生中 (playing): 音声が再生され、`heardRanges` / `damageRanges` の記録が進行する。敵出現は `waves[].atMs` で制御されるため、音声タイムラインと独立に配置できる
- 余韻 (outro): 音声終了後 `MissionMaster.outroMs` の間は余韻として戦闘が継続する。この間も noiseLevel は影響するが、記録対象の音声はない

`durationMs` は音声再生時間ではなくミッション全体の長さを指すため、以下の関係になります:

```
durationMs = audioStartDelayMs + 音声の長さ + outroMs
```

## 難易度による聴取パラメータの変化

全体設定の `Difficulty` および各ミッションの `dangerLevel` は、ノイズまわりのパラメータに修飾をかけます。

| パラメータ | calm での傾向 | terminal での傾向 |
|---|---|---|
| `hearingThreshold` | 高め（聴きやすい） | 低め（すぐ聴取不可になる） |
| `noiseDecayRate` | 速い（すぐ回復） | 遅い（ノイズが残る） |
| `noiseDamage` 倍率 | 低い | 高い |

具体的な修飾値は `DifficultyModifiers`（`05_データ構造` 参照）で定義します。
