# 01 STG / SF リファレンスから MAGNOLIA に取り入れる原則

作成日: 2026-04-28
目的: 他作品やデザインシステムから「見た目」を借りるのではなく、MAGNOLIA に移植できる設計原則へ変換する。

## 0. 結論

MAGNOLIA の問題は、単に「装飾が足りない」ことではない。むしろ、装飾・発光・グリッチ・粒子・罫線がそれぞれ別の理由で増えており、すべてが同じ世界の同じ物理法則から生まれているように見えない点が主因である。

採用すべき核は次の 5 つ。

1. 弾幕は攻撃ではなく、通信空間の構文として設計する。
2. UI は「メニュー」ではなく、壊れかけの通信システムの計測器として設計する。
3. 色は増やさず、階層、太さ、密度、余白、アルファで情報差を作る。
4. グリッチは汎用装飾ではなく、欠損・同期ズレ・受信不良の 3 種だけに意味を絞る。
5. モード遷移は画面切替ではなく、同じ信号が別の解析層へ移る変換として見せる。

## 1. 東方 / 弾幕 STG から取るもの

東方的な弾幕の美しさは、単に弾数が多いことではなく、画面全体が一時的な模様として成立し、その模様の中にプレイヤーが読むべき「安全な道」があることにある。

MAGNOLIA では敵弾を「敵の意思ある攻撃」としない方針が既にある。これは弾幕美学と相性がよい。つまり、当たらない弾、画面外へ流れる弾、遠くで模様だけを作る弾にも意味を持たせられる。ただし、それを「無駄弾」として足すのではなく、通信の乱れ、帯域の混雑、残響、反復送信、欠損パケットとして定義する。

### 採用する原則

弾幕パターンには、ゲームプレイ役割と視覚役割の両方を持たせる。

- ゲームプレイ役割
  - 通路を閉じる
  - 進行方向を誘導する
  - 安全地帯を遅れて開く
  - プレイヤーを静かに押し戻す
  - 解析率を取りに行くリスクを作る
- 視覚役割
  - 通信波形の周期を示す
  - 音声の句読点を示す
  - ノイズ源の種類を示す
  - ミッション本文の感情の波を示す
  - 余韻の残響を残す

### MAGNOLIA 向け弾幕ファミリー

既存の `bp_radial_burst`, `bp_spiral_stream`, `bp_b1_core_burst`, `bp_c1_pressure_ring` などは、すでに非追尾の幾何学弾幕として良い方向にある。ここに、視覚的な意味名を追加する。

- carrier wave
  - 円形・放射状。通信の基礎波。チュートリアルや静かなミッションに使う。
- packet rain
  - 小さな菱形や短い粒が斜めに流れる。受信パケットの雨。背景と弾の中間に置ける。
- compression band
  - 画面の一部を横切る密度の高い帯。音声の圧縮・歪みを示す。
- residual arc
  - 当たり判定は少ないが、弧がゆっくり残る。人の痕跡、余韻、聞き逃した声に使う。
- pressure ring
  - 現行の `bp_c1_pressure_ring` を主系統にする。危険度の上昇を円環の閉塞で示す。
- dead channel lattice
  - 格子状だが背景グリッドではなく、弾として一瞬だけ成立する。無人局の自動送信に使う。

### 避けるべきこと

- 弾数を増やして画面を派手にするだけの調整。
- 敵弾ごとに別々の見た目を増やすこと。
- 背景と敵弾が同じ輝度・同じ線幅になり、危険度が読めなくなること。
- 見た目のためだけに、当たる弾と当たらない弾の区別を曖昧にすること。

MAGNOLIA では「弾幕の美しさ」と「聴取の可読性」を同時に守る必要がある。背景演出は敵弾より 2 段階暗く、HUD は敵弾より 1 段階上の読みやすさを持つ、という階層を固定する。

## 2. NieR:Automata から取るもの

NieR:Automata の UI は、SF でありながら機械的な冷たさだけに寄っていない。重要なのは、単なるフラットデザインではなく、世界設定と UI の間に「控えめな非デジタルのモチーフ」を挿入している点である。

MAGNOLIA では、これを「譜面」ではなく「通信記録」「波形」「受信ログ」「欠落した本文」「局番」「古い機器の計測線」に置き換える。

### 採用する原則

- UI の主モチーフは直接的に描かない。
  - 花を描くのではなく、花弁のような非対称な余白、開きかけの円弧、途切れた縦罫で示す。
  - 通信を描くのではなく、波形、同期線、受信時刻、断片化された本文で示す。
- フラットな画面には、わずかな物理性を与える。
  - 画面端の暗部、微細グリッド、薄い歪み、古いモニタの曲面感を足す。
  - ただし、CRT 風に寄せすぎず、電子世界の質感として使う。
- 色に頼らない。
  - 選択状態は青を強くするだけでなく、線幅、余白、明度、括弧形状、行の密度で示す。
- 操作は見た目より先に単純化する。
  - 装備、アーカイブ、設定のすべてを別デザインにせず、同じ操作文法で読ませる。

### MAGNOLIA への変換

現行のメニュー画面は、装備、アーカイブ、設定の各タブがそれぞれ UI パーツとして成立しようとしている。しかし MAGNOLIA では「通信システム内の別機能」として統一した方がよい。

- 装備画面
  - equipment bay ではなく、自己修復・通信安定化モジュールの計測画面にする。
  - スロットはカードではなく、左の縦トラックに並ぶ接続ポートとして扱う。
- アーカイブ画面
  - ログ閲覧ではなく、復元済み信号の台帳にする。
  - 本文欄は紙面ではなく、聞こえた範囲だけが沈殿している受信フィールドにする。
- 設定画面
  - オプション一覧ではなく、診断パネルにする。
  - 音量やキー設定は「制御信号」の調整として表現する。

## 3. PRAGMATA から取るもの

PRAGMATA は、宇宙服、アンドロイド、月面、ハッキングという記号を持つ近未来 SF である。MAGNOLIA が直接取るべきなのは、明るいハイテク感ではなく、「人工物の硬さ」と「人間的な存在の違和感」が同居する構図である。

### 採用する原則

- 機械的なフレームの中に、人間的な痕跡を一点だけ置く。
  - 例: 完全に幾何学的な画面の中で、通信本文だけが少し不規則な行間で揺れる。
  - 例: 敵弾や背景は冷たい青だが、復元された人の声だけに温かい微光を使う。
- ハッキング表現を派手なコード雨にしない。
  - MAGNOLIA のハッキングは侵入ではなく受信と復元なので、画面を解体するより、失われた線が繋がり直す演出が合う。
- 主役の輪郭は常に読みやすくする。
  - 自機・敵機・基本弾は、どれだけ背景が抽象的でも輪郭が沈まないようにする。

## 4. NASA / 公式規格の視覚から取るもの

NASA 的な良さは、青や黒や宇宙っぽさだけではない。大きいのは、識別子、余白、禁則、支持グラフィックが明確に管理されていることだ。

MAGNOLIA でも「美しい幾何学」は、自由な装飾ではなく、使ってよいもの・使ってはいけないものが明確な規格として管理されるべきである。

### 採用する原則

- ロゴ、タイトル、HUD、メニュー、戦闘エフェクトに同じ比率の余白を使う。
- 線の太さ、角丸、罫線、グリッド密度を画面ごとに変えない。
- ロゴやタイトルにだけ許される演出を定義する。
  - 例: title glitch はタイトル専用であり、通常 HUD の欠損表現とは別。
- 支持グラフィックを定義する。
  - 支持グラフィックとは、背景を豊かにするための補助形状で、ゲーム情報を持たないもの。
  - MAGNOLIA では `distant carrier line`, `quiet dust`, `archive index tick`, `peripheral vignette` など。

## 5. IBM Carbon から取るもの

IBM Carbon からは、黒・青・グレーを使うこと自体ではなく、色の役割分担と階層設計を取る。

### 採用する原則

- ニュートラル階層で空間を作り、青は行動・接続・選択に限定する。
- 追加色は少なく、意味がある時だけ使う。
- 暗いテーマでは、奥の層ほど暗く、手前の層ほどわずかに明るくする。
- UI component は色ではなく token を参照する。

### MAGNOLIA の色役割

- void
  - 最奥。黒に近い深い青。背景の基本。
- abyss
  - 少しだけ見える空間。探索・戦闘背景の基底。
- panel
  - UI の面。完全な黒ではなく、少し青い半透明。
- line
  - 構造線。低アルファの青白。
- signal
  - 操作、接続、選択、解析中の強調。
- memory
  - 人の痕跡。温かい琥珀。使用面積は極小。
- danger
  - 危険、聴取悪化、ノイズ強度。赤は乱用しない。
- recovery
  - 自己修復や安定化。緑は SF ゲーム的になりやすいため、原則として signal blue に寄せる。

## 6. PSO2 / オンライン RPG 系 UI から取るもの

PSO2 系の UI は情報量が多いが、戦闘中・探索中・メニュー中で異なる UI モードを同じ世界に載せる参考になる。

MAGNOLIA が取るべきなのは、多数のウィンドウや派手な通知ではなく、モード別に必要な情報密度を切り替える思想である。

### 採用する原則

- 探索中は常設 UI を少なくし、接近・発見・接続時だけ情報密度を上げる。
- 戦闘中は右パネルに必要情報を固定し、プレイ領域の可読性を守る。
- メニュー中は情報密度を上げてもよいが、操作ルールは探索・戦闘と同じにする。
- 通知は画面中央を奪わず、ログとして残す。

## 7. STG ミッション設計への具体適用

MAGNOLIA のミッションは、敵ウェーブではなく通信本文の時間構造に合わせて設計する。

### 1 ミッションの視覚タイムライン

1. 接続前
   - 探索画面上で通信アイコンが静かに強くなる。
   - 背景の粒子が接続点へわずかに流れる。
2. 接続
   - 自機の周囲に一度だけ scan ring。
   - 画面全体が暗転するのではなく、探索空間の線が縦 STG の座標へ再配置される。
3. intro
   - 弾は少ない。背景に carrier line が見える。
   - 最初の敵は「ノイズ源」として発生し、攻撃意思を感じさせない。
4. message body
   - 通信本文の句読点・声量・感情の変化に応じて弾幕ファミリーを切り替える。
   - 当たらない弾も、模様と時間構造を作るために使う。
5. overload
   - 弾密度ではなく、帯域の詰まりを示す圧縮帯や圧力リングでピークを作る。
   - グリッチは 1 系統の `SignalDistortion` に集約する。
6. outro
   - 敵弾を急に消さず、画面外へ流れ、残響だけが残る。
   - 報酬 UI は victory ではなく archive capture として出す。
7. 帰還
   - 戦闘画面が閉じるのではなく、記録された断片が探索画面上の通信ノードへ戻る。

## 8. メニュー設計への具体適用

### 画面の共通骨格

- 上部
  - system header: MAGNOLIA / current mode / selected channel
- 左
  - navigation rail: equipment / archive / settings
- 中央
  - selected list: 装備スロット、通信ログ、設定項目
- 右
  - detail instrument: 選択項目の詳細、本文、計測値
- 下部
  - control hint: 決定、戻る、閉じる、詳細

この骨格を崩さず、画面ごとの差は中央と右の表示密度だけにする。

### 装備画面

- スロットはカードではなく、接続ポート。
- 装備名は大きくしすぎず、カテゴリと状態を整列させる。
- 選択中は強い glow ではなく、focus bracket と小さな scan tick で示す。
- 新規入手 badge は pulsing ではなく、短い warm memory line にする。

### アーカイブ画面

- 通信ログ一覧は「ホイール」よりも、奥行きのある ledger track として設計する。
- 未復元部分は `???` だけでなく、欠損幅・薄いノイズ帯・時間軸の穴で見せる。
- 本文の読みやすさを最優先する。背景エフェクトは本文の背後ではなく、余白に逃がす。

### 設定画面

- 7 段階バーは矩形を 7 個並べるだけにしない。
- 低い値ほど暗い短冊、高い値ほど signal line が長くなる計測器にする。
- reduced flashing / low framerate はアクセシビリティ項目として、暖色や赤ではなく neutral な診断項目にする。

## 9. モード遷移への具体適用

唐突な切替を避けるため、モード間で 1 つ以上の視覚要素を持ち越す。

### 探索から戦闘

- 持ち越すもの: 通信ノード、scan ring、自機位置。
- 変換: 通信ノードが縦座標の敵発生点へ伸び、探索グリッドが戦闘背景の carrier line に変わる。
- 時間: 450〜700ms。長くしすぎない。

### 戦闘からリザルト

- 持ち越すもの: 最後の弾幕残響、通信本文、解析率。
- 変換: 残った弾が fragment glyph にほどけ、中央に archive capture panel が出る。
- 勝利演出にしない。あくまで記録の保存。

### リザルトから探索

- 持ち越すもの: fragment glyph。
- 変換: fragment glyph が探索マップ上の通信アイコンへ戻る。
- 自機は画面中央に瞬間移動させず、帰還位置を短い halo で示す。

### 探索からメニュー

- 持ち越すもの: HUD の線、ミニマップの円、現在エリア名。
- 変換: HUD の線が menu frame へ拡張する。
- メニュー背景は探索背景と別物にせず、同じ signal field の焦点を変えたものにする。

## 10. 採用しないもの

- 派手なサイバーパンク風コード雨。
- 常時走る強いグリッチ。
- ネオンカラーの多用。
- UI の全要素に glow を付けること。
- 黄金比・フィボナッチ・幾何学用語を装飾の正当化として使うこと。
- NASA 風のロゴ規格をそのまま模倣すること。
- IBM 風の企業 UI をそのまま貼ること。

MAGNOLIA の美しさは、情報が静かに組み上がること、人の痕跡だけが少し温かいこと、そして装飾が何かを語りすぎないことにある。
