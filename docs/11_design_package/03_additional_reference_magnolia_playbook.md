# 04 MAGNOLIA 固有のビジュアルプレイブック

作成日: 2026-04-28
目的: 外部リファレンスだけでは足りない、MAGNOLIA 固有の「儚さ」「瀟洒」「非言語的」「人工的」「温かみの残り香」を実装へ落とす。

## 0. なぜ追加リファレンスが必要か

STG、SF UI、NASA、IBM、NieR:Automata から得られる原則は有用だが、MAGNOLIA の中心にある感情はそれだけでは表現しきれない。

MAGNOLIA は、戦うゲームでありながら、勝利よりも聴取を扱う。派手な宇宙 SF ではなく、意思を失ったシステムの中に人間の痕跡が残っている世界である。したがって、一般的な「かっこいい SF UI」や「派手な弾幕」へ寄せると、すぐに主題から離れる。

この文書では、MAGNOLIA 固有の判断基準を定義する。

## 1. MAGNOLIA らしさの 6 原則

### 1. 静けさは空白ではなく、低密度の秩序で作る

地味な画面は、情報が少ないから地味なのではない。意味のない低密度が続くから地味に見える。

MAGNOLIA の静けさは、見えない遠方に秩序がある気配で作る。

実装例:

- 背景に薄い carrier line を置くが、中央は空ける。
- 粒子はランダムではなく、遠い流れに沿って動く。
- グリッドは全面に敷かず、計測中の領域だけに出す。
- 画面端にごく薄い vignette を置き、中央に無音の余白を作る。

### 2. 人間の痕跡は少ないが強い

温かみを出すために、常時 amber や手書き風の装飾を使うと安っぽくなる。MAGNOLIA では、画面の大半を人工的に保ち、特定の瞬間だけ温かい色や不規則さを出す。

実装例:

- 通信本文の復元範囲だけ、ほんの少し memory amber を含む。
- archive の送信者・宛先・時刻にだけ暖色の index tick を使う。
- mission clear の報酬ではなく、聞こえた言葉に amber を使う。
- 装備の入手演出も、宝箱的な豪華さではなく「保守記録が復元された」ように見せる。

### 3. 非言語性は説明不足ではない

非言語的にするとは、文字を減らすことではなく、文字に頼らず状態が読める形を作ることだ。

実装例:

- 通信強度は数値より先に線の長さと密度で読む。
- 未復元の本文は `???` だけでなく、欠損幅と時間軸の穴で読む。
- 接続可能な通信は、ラベルより先にアイコン周辺の場の歪みで分かる。
- 装備が変更可能かどうかは、ボタン文言より focus bracket と接続ポートの開閉で示す。

### 4. 人工的なものほど、ルールが明確である

人工的な美しさは、図形が規則的なことではなく、全ての図形に同じ生成規則があるように見えることで生まれる。

実装例:

- すべての panel は同じ stroke / corner / padding。
- すべての scan は同じ easing と lifetime。
- すべての glitch は `SignalDistortion`。
- すべての fragment は同じ diamond family。
- すべての background particle は同じ seeded field。

### 5. 瀟洒さは、目立たない部分の精度で出る

大きな絵より、線の終端、余白、アルファ、文字位置、選択時の微細な動きが重要。

実装例:

- パネル内の見出しと値の baseline を揃える。
- 行間を一定にし、本文欄だけ少し広げる。
- focus bracket は対象に密着させず、4〜8px 浮かせる。
- hover glow は広げず、線の明度だけ上げる。
- アイコンは中央揃えよりも、光学的な重心で調整する。

### 6. 儚さは、消える過程で作る

儚さは薄い色だけでは出ない。現れ方より、消え方が大事である。

実装例:

- scan ring は急に消さず、細くなりながら消える。
- 敵撃破は爆発ではなく、弧がほどけてノイズが静まる。
- fragment は回収時に強く光らず、吸い込まれて記録へ沈む。
- battle result は派手に出ず、残響が archive panel に固着する。

## 2. 画面別プレイブック

### タイトル

目的:

- ゲームの静けさを最初に示す。
- 強い物語説明をせず、電子世界の空気を作る。

構成:

- L0: 深い void。
- L1: 遠い signal dust。非常に低密度。
- L2: MAGNOLIA logo。glitch は時々だけ。
- L3: menu buttons。余白を広めに。

禁則:

- logo glitch を常時派手にしない。
- title screen だけ別の色体系にしない。
- 背景粒子を星空に見せすぎない。

### 探索画面

目的:

- 「まだ聴こえていない空間」を歩く感覚。
- 発見は驚きではなく、微かな受信の増加として見せる。

必要要素:

- 自機 trail。
- 視界境界。
- 探索済み領域の低密度 signal field。
- 未探索領域の情報欠損。
- 通信ノード周辺の微細な attraction。

改善方針:

- fog を単なる暗幕ではなく、情報密度の差にする。
- 通信アイコンは常に光らせず、距離と接続可能性に応じて脈動を変える。
- 2D map 上のアイコンは、通信 / 装備 / 調査 / 境界 / ワープで primitive を分ける。

### 戦闘画面

目的:

- 縦 STG として読める。
- 弾幕が通信ノイズの可視化として美しい。
- 勝敗ではなく聴取状態が主題になる。

必要要素:

- 背景は弾幕を邪魔しない。
- 敵機はノイズ源として、攻撃意思を持ちすぎない。
- 敵弾は危険だが、模様として美しい。
- 被弾は HP 減少ではなく、音声と字幕の欠損として見せる。

改善方針:

- 基本敵弾は現行品質を維持する。
- geo / lance / core / shard 系は、弾幕 role ごとに再分類する。
- hazard は派手な VFX ではなく、受信帯域の汚染として表現する。
- barrier gauge や support field は、STG 的な派手さを少し抑え、通信安定化の field として見せる。

### メニュー

目的:

- ゲーム外 UI ではなく、MAGNOLIA 内部端末。
- 装備、アーカイブ、設定が同じ装置の別機能に見える。

必要要素:

- 共通 header。
- navigation rail。
- list column。
- detail instrument。
- control hint。
- subdued backdrop。

改善方針:

- カード UI を減らす。
- 枠線と glow を減らす。
- 選択状態は focus bracket と data lane で示す。
- archive 本文は最も読みやすくする。
- settings のバーは、単なる UI widget ではなく計測器にする。

### ムービー / プレゼンテーション演出

目的:

- 説明ではなく、状態の変化を見せる。
- reboot、接続、復元、帰還を「信号が組み替わる」出来事として見せる。

改善方針:

- 現行の reboot sequence は良い素材として保持する。
- ただし、reboot 専用で終わらせず、transition primitive として抽出する。
- 大きな演出でも、画面全体の明滅ではなく、線の再配置と fragment の集積を主にする。

## 3. 形状ファミリー定義

### Ship family

意味:

- MAGNOLIA の操作焦点。
- 人ではなく、システムの端末。

現状:

- `ship-renderer.ts` に一元化済みで良い。
- solid / art variant の考え方も良い。

追加規則:

- 戦闘中は silhouette 優先。
- メニューや key visual では artDetailStrength を上げてよい。
- 被弾時に本体 silhouette を崩さない。上から desync を被せる。

### Noise source family

意味:

- 意思ある敵ではなく、通信を汚す発生源。

現状:

- 丸ベース敵機は良い。
- 中心円 + 軌道 + 欠けた弧は MAGNOLIA に合っている。

追加規則:

- 強敵ほど装飾を増やすのではなく、軌道の密度と欠損のパターンを変える。
- アイコンは攻撃性より信号種別を示す。
- 撃破時は爆発ではなく、軌道がほどける。

### Enemy bullet family

意味:

- 可視ノイズ。
- 当たる危険と、画面全体の模様の両方。

現状:

- `proj_enemy_basic` と `drawNoiseOrbProjectile` は良い。
- `proj_enemy_geo`, `lance`, `core`, `petal` は分類名が見た目ベースで、意味 role が不足している。

追加規則:

- `basic`: carrier noise。
- `petal`: residual / memory-adjacent には使わない。危険弾としての花弁化は慎重に。
- `geo`: packet / fragment との混同に注意。
- `lance`: directed interference。方向性が読める弾幕に使う。
- `core`: pressure / overload。

### Player bullet family

意味:

- 通信を安定させる解析波。
- 攻撃というより、ノイズ源の解像度を上げて消す。

現状:

- main は良い。
- 他の player projectile / sub arm effects は、もう少し整理が必要。

追加規則:

- player main は `signal` 色に寄せ、敵弾と混同させない。
- sub arms は色で差別化せず、形状とフィールド効果で差を出す。
- blast / melee は派手な衝撃波ではなく、局所的な静音化に見せる。

### Fragment / archive family

意味:

- 人の痕跡が保存可能な形になったもの。

現状:

- `drawBattleFragment` や marker 系に良い方向がある。

追加規則:

- diamond family に集中する。
- amber は fragment の中心ではなく、縁や一瞬の反射に使う。
- pickup 時は「取得」ではなく「記録へ沈む」。

## 4. 言葉を使わずに伝える状態表現

### 接続可能

- 通信アイコンの周辺に短い carrier lines が集まる。
- 中心は強く光らせない。
- Enter prompt は最後に出る。

### 未探索

- 黒く隠すだけでなく、signal field が存在しない状態にする。
- 視界円の外は、情報密度が薄く、線が途切れる。

### 聴取悪化

- 画面全体を赤くしない。
- subtitle と音声の desync を主にする。
- 右 HUD の noise meter を短く強調する。

### 解析進行

- 敵撃破数ではなく、ノイズ源が静まる感じを出す。
- ring / line の密度が整理される。
- 解析率が上がる時、背景が少しだけ澄む。

### 復元進行

- 本文が増える。
- 欠損 mask が減る。
- amber はこの時だけ少し使う。

## 5. チーム内レビュー用チェックリスト

新しい画面やエフェクトをレビューする時は、次の問いを使う。

- これは MAGNOLIA のどの状態を示しているか。
- loss / desync / noise のうちどれか。
- dust / packet / fragment / spark のうちどれか。
- ring / line / diamond / rectangle の意味が既存と衝突していないか。
- この色は token のどれか。
- memory amber は使いすぎていないか。
- glow は focus / active signal のために使われているか。
- この motion は productive / system communication / expressive transition / ambient のどれか。
- reduced flashing で情報が失われないか。
- プレイヤーが弾と背景を分離して読めるか。
- メニューを閉じた後、探索や戦闘と同じ世界に戻った感覚があるか。

## 6. デザイン規則の短い版

エンジニアやデザイナーが迷った時は、この 10 行を参照する。

1. 派手にせず、意味を強くする。
2. 青は信号、琥珀は人の痕跡、赤は聴取危機。
3. グリッチは 1 系統。欠損、同期ズレ、ノイズだけ。
4. 円は場、弧は不完全な記録、線は接続、菱形は断片。
5. 背景は弾幕より 2 段階暗い。
6. UI はカードではなく計測器。
7. 遷移は暗転ではなく、信号の再配置。
8. 人間の温かさは少量で出す。
9. 消え方を丁寧にする。
10. すべての装飾に理由を持たせる。
