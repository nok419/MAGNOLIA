# フロントエンド_フェーズ1

# フェーズの目的

フェーズ1の frontend は、戦闘 renderer と battle UI を content preset / renderState 駆動へ移す段階です。旧 workorder の battle renderer 正本化と、戦闘を通信保護の画面にする作業をこのフェーズにまとめます。

# 両チーム共通の構想と制約

- 表示層は snapshot / renderState / ViewModel / PresentationRequest を描画する。content 全量や save 内部から未発見情報、報酬、衝突、復元状態を推測しない。
- `content/gameplay/visual-presets`、`hitbox-presets`、`background-presets`、`presentation-cues.json` は現行 content の正本として扱う。
- mission ID、enemy ID、projectile ID を見て renderer に新しい個別分岐を追加しない。差分は content preset、rendererKind、presentation cue、renderState の公開フィールドに置く。
- 色は `apps/web/src/styles/tokens.css` と `apps/web/src/render/shared/canvas-palette.ts` の semantic role を正本にする。`threatNoise` は被弾、聴取不能、hazard 予兆または active hazard に限定する。
- `reduceFlashing` と `lowFrameRateMode` は新規表現、presentation cue、Canvas cache の受け入れ条件に含める。

# 棚卸し判断

- `buildEntityRendererKeys()` は `mission:${missionId}:${legacyEntityId}`、legacy ID、`mission:${missionId}` を候補に入れており、現行方針と衝突する。
- `enemy-renderer.ts` と `projectile-renderer.ts` は visualPresetId を入口にしているが、profile の中身は TypeScript に手書きされている。
- `background-renderer.ts` は preset ID switch が中心で、background preset の density/intensity を十分に使っていない。
- `magnetic-disaster.ts` は hazard visualPresetId を受けておらず、gentle/standard 差分を content で制御しづらい。
- App / Presentation 境界は現行でかなり実装済みのため、旧チケットを再発行せず、battle UI の具体化に絞る。

# 進行管理

- FE-1-01、FE-1-02、FE-1-03 は BE-1-01 と BE-1-04 の contract 確定後に完了判定する。
- FE-1-04 は BE-1-03 の renderState 追加が必要。固定値や local 推測で完成扱いにしない。
- FE-1-05 は FE-0-01、FE-0-03 の共通部品を前提にする。

# FE-1-01 renderer dispatch を preset / rendererKind に限定する

タグ: `[phase:1] [team:frontend] [battle-renderer] [blocking]`

## 現状確認

- `buildEntityRendererKeys()` が mission ID と legacy entity ID を fallback key として扱っている。

## 作業

- 通常経路では `visualPresetId` と `rendererKind` だけで dispatch する。
- migration が必要な旧 ID 対応は限定ファイルへ移す。
- enemy / projectile renderer の registry key から `mission:*`、`proj_*`、`enemy_*` 由来の通常 fallback を外す。
- unknown preset は silent default に落とさず、開発時 warning または validator error と整合させる。

## 依存関係と進行管理

- BE-1-01 の contract 確定後に完了判定する。

## 受け入れ条件

- battle renderer の通常経路で `missionId` を見て描画分岐していない。
- 新規 mission を追加しても renderer registry に mission key を足さない。

# FE-1-02 enemy / projectile renderer を preset 値と palette helper で描く

タグ: `[phase:1] [team:frontend] [battle-renderer] [preset] [palette]`

## 現状確認

- enemy profile と projectile profile に色、glow、orbitScale、trail などが手書きされている。

## 作業

- enemy renderer は `paletteRole`、`orbitScale`、`glyphCount`、`glowIntensity`、`motionProfile` を preset から読む。
- projectile renderer は `trailKind`、`auraKind`、`radiusScale`、`motionSmear`、`glowIntensity` を preset から読む。
- 直接色指定を `hex(role)`、`rgba(role, alpha)`、`gradientStop(role, alpha)` へ移す。
- 特例説明は renderer comment ではなく content preset の description / migration note へ寄せる。

## 依存関係と進行管理

- BE-1-01 と BE-1-02 の型・collision 方針と合わせる。

## 受け入れ条件

- `vis_enemy_*` の paletteRole を変えるだけで enemy の色調が変わる。
- `vis_bullet_*` の trailKind を変えるだけで trail の種類が変わる。
- 見た目の radiusScale は collision に影響しない。

# FE-1-03 background / hazard renderer を content preset で制御する

タグ: `[phase:1] [team:frontend] [battle-renderer] [background] [hazard]`

## 現状確認

- background renderer は preset ID switch に寄っており、magnetic disaster renderer は直接色と固定強度が多い。

## 作業

- `BattleRenderState.background` の `residualWarmth`、`structureDensity`、`dustDensity`、`scanlineIntensity`、`vignetteStrength` を描画に反映する。
- active hazard の解決済み visual preset を受け取り、強度、予兆時間、色 role、reduceFlashingVariant を使う。
- `ThreatNoiseField` の共通 effect を使い、threatNoise を常時装飾に使わない。

## 依存関係と進行管理

- BE-1-04 の background/hazard 解決値が前提。

## 受け入れ条件

- background preset の密度値を変えると背景密度が変わる。
- hazard gentle/standard の差が TypeScript 固定値ではなく preset で表される。
- `reduceFlashing` true では点滅が alpha、線幅、形状差に置き換わる。

# FE-1-04 戦闘画面を通信保護の UI に作り直す

タグ: `[phase:1] [team:frontend] [battle-ui] [presentation] [depends-on-backend]`

## 現状確認

- 戦闘画面は進行度、字幕、敵弾を表示しているが、「守っている言葉」「欠けた範囲」「帯域回復」が分かりにくい。

## 作業

- battle HUD に `聴取安定` と `解析進行` の 2 meter を表示する。
- 字幕欠損は空白だけでなく、欠けた範囲が分かる mask、glyph、underline で示す。
- `reduceFlashing` true では文字の高速入れ替えを止め、固定 mask にする。
- fragment の発生、移動、回収、保存を `ResidualFragment` から restoration へ移る motion として描く。
- 敵撃破時はノイズが薄くなる、字幕下線が整う、解析 meter が進む形で帯域回復を示す。

## 依存関係と進行管理

- BE-1-03 の BattleRenderState 拡張が前提。

## 受け入れ条件

- result overlay を見る前に、守れた言葉と欠けた言葉が分かる。
- frontend が chunk 本文や mission ID を直接読んで状態を推測していない。

# FE-1-05 battle / result / menu の surface grammar を初期移行する

タグ: `[phase:1] [team:frontend] [ui] [surface]`

## 現状確認

- common component はあるが、画面側 CSS に `battle-*panel`、`panel-card`、`equipment-*` などの独自 surface が残っている。

## 作業

- battle HUD、battle result、menu の主要 panel から common component へ寄せる。
- panel の中に同じ見た目の panel を重ねない。
- border は focus、選択、境界に限定する。
- blur は menu、modal、overlay の背面分離に限定する。
- subtitle と prompt が vignette、blur、scanline で読みにくくならないよう確認する。

## 受け入れ条件

- battle result と menu detail が同じ surface grammar で見える。
- 常時発光する太線が増えていない。
- prompt と subtitle の可読性が低下していない。
