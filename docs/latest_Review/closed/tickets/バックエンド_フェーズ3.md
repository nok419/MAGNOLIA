# バックエンド_フェーズ3

# フェーズの目的

フェーズ3は、フェーズ0〜2で固定した contract と ViewModel を保守しやすい形に整理する段階です。content 追加時の手作業を減らし、active/prototype/deprecated の運用、archive 作成手順、最終回帰テストを仕上げます。

# 両チーム共通の構想と制約

- 表示層は snapshot / renderState / ViewModel / PresentationRequest を描画する。content 全量や save 内部から未発見情報、報酬、衝突、復元状態を推測しない。
- `content/gameplay/visual-presets`、`hitbox-presets`、`background-presets`、`presentation-cues.json` は現行 content の正本として扱う。
- mission ID、enemy ID、projectile ID を見て renderer に新しい個別分岐を追加しない。差分は content preset、rendererKind、presentation cue、renderState の公開フィールドに置く。
- 色は `apps/web/src/styles/tokens.css` と `apps/web/src/render/shared/canvas-palette.ts` の semantic role を正本にする。`threatNoise` は被弾、聴取不能、hazard 予兆または active hazard に限定する。
- `reduceFlashing` と `lowFrameRateMode` は新規表現、presentation cue、Canvas cache の受け入れ条件に含める。

# 棚卸し判断

- `load-content-bundle.ts` は静的 import で多数の JSON を取り込んでいる。現時点では動いているが、content 追加時の import 追加漏れが起き得る。
- `content-classification.json`、`deprecated`、`prototypes` は存在するが、active bundle から除外する運用を validator と loader の両方で固定する必要がある。
- provided archive には `packages/*/dist`、`tools/content-validator/dist`、`.tsbuildinfo`、`__MACOSX` などが含まれていた。

# 進行管理

- BE-3-01 は BE-0-01、BE-0-03、BE-1-01 の後に行う。schema と contract が固まる前に loader 自動化を行わない。
- BE-3-02 は BE-0-03 の validator と BE-2-02 の mission/content 修正後に行う。
- BE-3-03 は FE-3-03 の re-export cleanup と同じ release に合わせる。
- BE-3-04 はフェーズ全体の最終確認として行う。

# BE-3-01 content import manifest または loader 生成を導入する

タグ: `[phase:3] [team:backend] [content-loader] [maintenance]`

## 現状確認

- `packages/persistence/src/load-content-bundle.ts` は content JSON を静的 import しており、新規 content 追加時に import 追加漏れの余地がある。

## 作業

- content directory から manifest を生成するか、環境に合う import glob を導入する。
- manifest は validator の対象にし、実在ファイルとの差分があれば失敗させる。
- generated manifest を使う場合は、生成手順と更新手順を root script に追加する。

## 受け入れ条件

- 新しい mission / enemy / projectile / preset を追加しても、TypeScript import の追加漏れで bundle から落ちない。
- manifest と実ファイルの差分が validator で検出される。

# BE-3-02 active / prototype / deprecated の lifecycle を固定する

タグ: `[phase:3] [team:backend] [content] [validator]`

## 現状確認

- `content/gameplay/prototypes`、`deprecated`、`content-classification.json`、`migrated-id-map.json` が存在する。

## 作業

- active bundle に含める content の条件を docs と validator に固定する。
- prototype / deprecated の参照が active mission から辿れる場合は失敗にする。
- migration ID が必要な場合は `migrated-id-map.json` に残し、renderer や session の通常経路に legacy ID を戻さない。

## 受け入れ条件

- active build に不要な prototype content が混ざらない。
- prototype を active 化する手順が docs にあり、validator で確認できる。

# BE-3-03 archive 作成手順と release artifact を分離する

タグ: `[phase:3] [team:backend] [repo] [archive]`

## 現状確認

- provided archive には生成物や OS metadata が含まれていた。`tools/create-source-archive.mjs` は存在するが、実際の提出物が clean ではない。

## 作業

- source archive から `__MACOSX/`、`.DS_Store`、`node_modules/`、`.vite/`、`dist/`、`*.tsbuildinfo` を除外する。
- review 用 source archive と実行用 release artifact の作成手順を分ける。
- archive 作成後に禁止ファイル検査を走らせる。

## 受け入れ条件

- clean archive に build artifact、cache、OS metadata が含まれない。
- root workspace、packages、tools、docs、content は source review に必要な範囲で含まれる。

# BE-3-04 state transition / save export の最終回帰テストを揃える

タグ: `[phase:3] [team:backend] [test] [regression]`

## 現状確認

- フェーズ1・2で battle state、explore signal state、menu ViewModel、mission beat、save normalizer が変更される。

## 作業

- title → slot select → explore → scan → mission → result → equipment → archive → save/reload の一連の状態をテストする。
- old save migration test と new save roundtrip test を用意する。
- ViewModel 生成と command 可否が save/reload 後も一致するか確認する。

## 受け入れ条件

- save/reload 後に探索識別、装備状態、mission clear、archive 既読が維持される。
- 一時 presentation state が永続化されない。
