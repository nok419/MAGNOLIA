# フロントエンド_フェーズ2

# フェーズの目的

フェーズ2の frontend は、探索、map / minimap、menu / equipment / archive を ViewModel と shared renderer に寄せる段階です。戦闘 renderer の基礎を固めた後、探索の遊びと画面間の表示規則を整えます。

# 2026-04-30 実装結果

- FE-2-01: `ExploreCanvas.tsx` を host に縮小し、scene、reboot、reboot-settle、boundary release、restricted boundary、nav cue、player を `apps/web/src/render/explore/*` に分けた。
- FE-2-02: `signalHints.detectedState` を描画に反映し、未識別通信は正確座標ではなく方角と距離帯で示す。identified / recorded は距離帯上の種別記号で示す。
- FE-2-03: `MapScreen` の Canvas 描画を `apps/web/src/render/map/map-renderer.ts` に移し、MiniMap の直接色指定を `canvas-palette` helper に寄せた。
- FE-2-04: `EquipmentPanel`、`ArchivePanel`、`MenuScreen` を ViewModel 入力にし、価格、強化可否、未取得 masking、アーカイブ metadata / body の計算を UI から削除した。
- FE-2-05: `battle.mission.beat` を `intentTag` ベースで battle presentation layer と subtitle tone に反映した。mission ID 分岐は追加していない。

# 両チーム共通の構想と制約

- 表示層は snapshot / renderState / ViewModel / PresentationRequest を描画する。content 全量や save 内部から未発見情報、報酬、衝突、復元状態を推測しない。
- `content/gameplay/visual-presets`、`hitbox-presets`、`background-presets`、`presentation-cues.json` は現行 content の正本として扱う。
- mission ID、enemy ID、projectile ID を見て renderer に新しい個別分岐を追加しない。差分は content preset、rendererKind、presentation cue、renderState の公開フィールドに置く。
- 色は `apps/web/src/styles/tokens.css` と `apps/web/src/render/shared/canvas-palette.ts` の semantic role を正本にする。`threatNoise` は被弾、聴取不能、hazard 予兆または active hazard に限定する。
- `reduceFlashing` と `lowFrameRateMode` は新規表現、presentation cue、Canvas cache の受け入れ条件に含める。

# 棚卸し判断

- `ExploreCanvas.tsx` は 2553 行で、canvas host、scene、reboot、release、boundary、nav cue、player draw が同居している。
- `MapScreen` は ViewModel 入力であり、raw content 問題ではない。対象は shared renderer 化と palette 化に絞る。
- `EquipmentPanel` は raw content / profile から表示計算している。backend ViewModel 受け取り後に置換する。
- Explore signal hint の一部 field は既に存在する。frontend チケットは未実装 field を受け取る表示と、正確座標を出さない描画に絞る。

# 進行管理

- FE-2-01 は backend 依存なしで開始できる。ただし signal UI の完成は BE-2-01 後に行う。
- FE-2-02 は BE-2-01 の完了後に完了判定する。
- FE-2-04 は BE-2-03 の ViewModel が必要。旧 props との併用期間を置いてから削除する。
- FE-2-05 は BE-2-02 の PresentationRequest が必要。mission ID 分岐による仮実装は行わない。

# FE-2-02 探索を signal-search UI として実装する

タグ: `[phase:2] [team:frontend] [explore-ui] [depends-on-backend]`

## 現状確認

- scan pulse、signal hints、nearestTransmissionStrength の入口はあるが、探索段階が見分けにくい。

## 作業

- signal hint を `ghost`、`identified`、`recorded` の段階で描き分ける。
- `ghost` では方角と距離帯だけを示し、正確な座標に marker を置かない。
- `identified` ではカテゴリとおおよその位置、`recorded` では map / minimap に残る表示にする。
- scan pulse は `SignalPulse` を使う。通信は円弧と短い縦線、collectible は小さい菱形、repair は短い水平線 2 本にする。
- 常設 HUD を減らし、signal hint と interaction prompt を主情報にする。

## 依存関係と進行管理

- BE-2-01 の signal hint 拡張が前提。

## 受け入れ条件

- 未識別通信の正確な座標が表示されない。
- scan により方角、距離帯、カテゴリ、信号強度が分かる。
- 一度識別・記録したものは map / minimap に残る。

# FE-2-03 MapScreen と MiniMap を shared renderer 化する

タグ: `[phase:2] [team:frontend] [map] [renderer] [palette]`

## 現状確認

- `MapScreen` は `WorldMapViewModel` を入力にしているが、Canvas draw 関数が screen component 内にあり、MiniMap と表現が分裂しやすい。

## 作業

- `drawMapCanvas`、`drawMapGrid`、`drawMapFog`、`drawMapVisionWave`、`drawAreaPoint`、`drawPlayerPoint` を `apps/web/src/render/map/*` へ移す。
- `drawTransmissionMarker`、`drawCollectibleMarker` を shared marker として維持し、map / minimap / explore で同じ記号体系を使う。
- fog、vision、grid は `ArtificialGrid` と `SignalPulse` に寄せる。
- `MiniMap` の直接色指定を palette helper へ移す。

## 受け入れ条件

- map / minimap / explore の transmission と collectible icon が同じ記号体系になる。
- `MapScreen.tsx` から直接色指定がほぼ消える。
- map は引き続き full content ではなく ViewModel だけを入力にする。

# FE-2-04 Equipment / Archive / Menu を ViewModel 入力へ移行する

- frontend が未発見情報や報酬を raw content から推測しない。
