# バックエンド_フェーズ0

# フェーズの目的

フェーズ0は、後続の描画・探索・CRUD 改修が安全に進められる状態を作る段階です。対象は root workspace、packages、content、docs、validator、アーカイブ作成手順です。

現行アーカイブを確認した結果、旧 workorder の一部前提は更新が必要です。`packages/contracts`、`packages/game-session`、`packages/persistence`、`tools/content-validator` は現行アーカイブに含まれています。一方で root の `package.json`、`tsconfig.base.json`、lockfile、CI 定義は確認できません。`tools/content-validator/dist/validate-content.js` は `content validation passed (90 JSON files)` まで通りますが、root script と CI 接続がなく、node visibility、docs/content tree 差分、active/prototype/deprecated の運用強制などが不足しています。

# 両チーム共通の構想と制約

- gameplay の正しさは `packages/game-session`、save と正規化は `packages/persistence`、content の正本は `content/gameplay`、表示は snapshot / renderState / ViewModel / PresentationRequest を描画する層として扱う。
- `content/gameplay/visual-presets`、`hitbox-presets`、`background-presets`、`presentation-cues.json` は現行 content に存在する。以後は「復元」ではなく「正本として必ず消費し、検証する」方針にする。
- 表示層で mission ID、enemy ID、projectile ID を見て個別分岐を増やさない。差分は content preset、rendererKind、presentation cue、renderState の公開フィールドに置く。
- 色は `apps/web/src/styles/tokens.css` と `apps/web/src/render/shared/canvas-palette.ts` の semantic role を正本にする。`threatNoise` は被弾、聴取不能、hazard 予兆または active hazard に限定する。
- `reduceFlashing` と `lowFrameRateMode` は新規表現、presentation cue、Canvas cache の受け入れ条件に含める。
- ソースアーカイブには生成物、cache、OS metadata を含めない。

# 棚卸し判断

- 旧チケットの「packages がアーカイブ外」は現行では不正確。packages はあるが root workspace が欠けており、build/CI の入口が未整備というチケットに修正する。
- 旧チケットの「content validator を新設」は現行では不正確。validator は存在するため、root script/CI 接続と不足ルール追加のチケットに修正する。
- 旧チケットの「visual/hitbox/background preset を復元」は現行では不正確。preset JSON は存在するため、backend は型・loader・session の必須化、frontend は renderer 消費へ分割する。
- App / Presentation 境界は現行コードで `battleEvents`、`exploreEvents`、`transitionEvents` の配線が進んでいる。大規模チケットとしては除外し、フェーズ0の frontend 側で回帰確認のみ残す。
- MapScreen は現行で `WorldMapViewModel` を入力にしている。full content を読む問題としては扱わず、フェーズ2の frontend 側で renderer 分割と palette 化に絞る。

# 進行管理

- BE-0-01、BE-0-02、BE-0-03 はフェーズ1開始前の gate とする。
- FE-0-01 の token/palette 整備は BE-0-02 の palette 正本更新と並行してよい。ただし最終 token 名は BE-0-02 完了時に固定する。
- validator の追加ルールが content 修正を要求する場合、content 修正は BE-0-04 で扱い、frontend 側で暫定回避しない。

# BE-0-01 root workspace と clean build gate を復旧する

タグ: `[phase:0] [team:backend] [gate] [blocking] [repo]`

## 現状確認

- `apps/web/tsconfig.json`、各 package の `tsconfig.json` は `../../tsconfig.base.json` を extends しているが、root に `tsconfig.base.json` が存在しない。
- root の `package.json` と workspace 定義が確認できない。
- アーカイブ内に `__MACOSX`、`.DS_Store`、`apps/web/node_modules/.vite`、`apps/web/dist`、`*.tsbuildinfo`、各 package/tool の `dist` が含まれている。
- `tools/create-source-archive.mjs` は生成物除外の意図を持っているが、今回の提供 zip には生成物と OS metadata が混入している。

## 作業

- root に `package.json`、workspace 定義、`tsconfig.base.json`、lockfile、CI 定義を復旧する。
- root scripts を少なくとも次の形で用意する。
  - `npm run build`
  - `npm run typecheck`
  - `npm run content:validate`
  - `npm run style:audit`
- source archive 作成手順を root script から実行できるようにする。
- source archive から次を除外する。
  - `__MACOSX/`
  - `.DS_Store`
  - `._*`
  - `node_modules/`
  - `.vite/`
  - `.vite-temp/`
  - `dist/`
  - `*.tsbuildinfo`
- source archive と実行用 artifact を分ける。source archive に package dist を含めない。

## 受け入れ条件

- clean checkout または clean 展開後に、root で `npm install`、`npm run build`、`npm run content:validate`、`npm run style:audit` が実行できる。
- source archive に生成物、cache、OS metadata が含まれない。
- `apps/web` 単独でなく、packages と tools を含む workspace として型検査できる。

# BE-0-03 content validator を root script と CI に接続し、不足ルールを追加する

タグ: `[phase:0] [team:backend] [tooling] [validator] [blocking]`

## 現状確認

- `tools/content-validator/src` と `dist` は存在する。
- `node tools/content-validator/dist/validate-content.js` は現行 content 90 JSON に対して通る。
- root script と CI 接続は確認できない。
- 現行 validator では、area visibility より広い node visibility が検出されない。

## 作業

- root に `npm run content:validate` を追加し、validator を workspace の正式コマンドにする。
- CI で `content:validate` を必須化する。
- 既存ルールを維持しつつ、以下を追加する。
  - map node の `visibilityConditionId` は所属 area より広くならない。例外を許す場合は `allowOutOfAreaHint: true` のような明示 field を要求する。
  - docs に記載された content directory と実在 directory の差分を検出する。
  - `content-classification.json` と実ファイル配置、loader の active bundle が一致するかを検出する。
  - active / prototypes / deprecated の分類漏れを検出する。
  - visual preset / hitbox preset / background preset / presentation cue の schema と coverage を継続検証する。
  - content にある field が renderer/session で消費されていない場合、少なくとも警告として出せる仕組みを作る。例: `trailKind`、background density、hitbox shape。
- validator の出力は、file path、対象 ID、問題文が分かる形にする。

## 受け入れ条件

- `npm run content:validate` が root から通る。
- visual preset を削除した場合、該当 enemy / projectile / hazard の検証が失敗する。
- presentation cue に `reduceFlashingVariant` がない場合、検証が失敗する。
- `node_collect_analysis_circuit` のような area visibility より広い node が、修正または明示例外なしでは検出される。
- docs/content tree の矛盾が validator または専用 audit で検出される。
