# バックエンド_フェーズ1

# フェーズの目的

フェーズ1は、戦闘描画と戦闘体験を content preset と session contract に接続する段階です。visual preset、hitbox preset、background preset、presentation cue は存在しているため、復元ではなく、必須 contract 化と実使用を対象にします。

# 両チーム共通の構想と制約

- 表示層は snapshot / renderState / ViewModel / PresentationRequest を描画する。content 全量や save 内部から未発見情報、報酬、衝突、復元状態を推測しない。
- `content/gameplay/visual-presets`、`hitbox-presets`、`background-presets`、`presentation-cues.json` は現行 content の正本として扱う。
- mission ID、enemy ID、projectile ID を見て renderer に新しい個別分岐を追加しない。差分は content preset、rendererKind、presentation cue、renderState の公開フィールドに置く。
- 色は `apps/web/src/styles/tokens.css` と `apps/web/src/render/shared/canvas-palette.ts` の semantic role を正本にする。`threatNoise` は被弾、聴取不能、hazard 予兆または active hazard に限定する。
- `reduceFlashing` と `lowFrameRateMode` は新規表現、presentation cue、Canvas cache の受け入れ条件に含める。

# 棚卸し判断

- `ContentBundle` には `contentVisualPresets?`、`contentHitboxPresets?`、`backgroundPresets?` があるが、frontend renderer への必須 contract としては弱い。
- `packages/game-session/src/battle-world.ts` の `resolveHitRadius()` は hitbox preset ID の文字列から半径を推測しており、hitbox JSON 正本という方針と合わない。
- background と hazard は ID が渡っているが、density、intensity、gentle/standard 差分を十分に表示へ渡せていない。
- 戦闘 UI に必要な current chunk、欠損範囲、解析進行、聴取安定、fragment origin は、frontend が local に推測しないよう session から渡す必要がある。

# 進行管理

- BE-1-01 は FE-1-01、FE-1-02、FE-1-03 の前提。contract 確定までは frontend の legacy fallback 完全削除を完了扱いにしない。
- BE-1-02 は FE-1-02 と並行可能。ただし collision test が通るまでは visual radius の調整を gameplay 調整として扱わない。
- BE-1-03 は FE-1-04 の前提。戦闘 UI は暫定の local 推測で完成扱いにしない。
- BE-1-04 は FE-1-03 の前提。background/hazard renderer が preset 値を受け取る形を先に固定する。

# BE-1-01 visual/background/hazard preset contract を必須化する

タグ: `[phase:1] [team:backend] [contract] [content] [blocking-for-frontend]`

## 現状確認

- preset JSON は存在するが、renderer はまだ ID registry と手書き profile に依存している。
- `ContentBundle` の preset table は optional に近い扱いで、missing preset を型で防ぎにくい。

## 作業

- `packages/contracts` に enemy / projectile / hazard / background の描画用安定型を定義する。
- session が `BattleRenderState` を作る時点で、ID だけでなく `rendererKind`、`paletteRole`、`orbitScale`、`glyphCount`、`trailKind`、`auraKind`、`radiusScale`、背景 density/intensity などの解決済み値を渡せるようにする。
- legacy ID fallback は migration adapter に閉じ込め、renderer registry に `mission:*` や `proj_*` を増やさない。

## 受け入れ条件

- active enemy / projectile / hazard / background の preset が欠けると loader または validator で失敗する。
- `vis_enemy_a1.json` の `orbitScale` や `glyphCount` を変更すると、frontend が個別分岐を足さずに変更を受け取れる。
- unknown preset の error/warning 方針が contracts または validator に書かれている。

# BE-1-02 hitbox preset JSON を collision の正本にする

タグ: `[phase:1] [team:backend] [game-session] [collision] [test]`

## 現状確認

- hitbox preset JSON は存在するが、現行 collision は ID 文字列の `small`、`medium`、`large`、`thin` などから半径を推測している。

## 作業

- hitbox preset の型を contracts に固定する。円、楕円、複合形状のうち最初の対応範囲を明記する。
- enemy、projectile、player の collision 半径または形状を `hitboxPresetId` から解決する。
- visual preset の `radiusScale`、`orbitScale`、glow は collision に影響しないようにする。
- visual preset 変更では collision が変わらず、hitbox preset 変更では collision が変わる unit test を追加する。

## 受け入れ条件

- 当たり判定の値が hitbox JSON から取得される。
- 文字列 ID の部分一致で collision 値を決める処理が通常経路に残っていない。
- 見た目調整と gameplay 調整の境界をテストで確認できる。

# BE-1-03 戦闘通信 UI のための BattleRenderState を拡張する

タグ: `[phase:1] [team:backend] [battle] [presentation] [blocking-for-frontend]`

## 現状確認

- presentation event の配線は進んでいるが、frontend が「守っている言葉」「欠けた範囲」「帯域回復」を表示するには battle HUD 情報が不足する。

## 作業

- `currentChunkId`、`currentChunkProtectedRatio`、`noiseLevel`、`hearingThreshold`、`analysisRate`、`newlyLostRange`、`newlyRecoveredRange` を追加する。
- fragment の `origin`、`createdAtMs`、`sourceChunkId` と、敵撃破後の `noiseSourceCleared` または同等の PresentationRequest を出す。
- `presentation-cues.json` の `battle.subtitle.damage`、`battle.fragment.recovered`、`battle.noiseSource.clear` と renderState の関係を docs に追記する。

## 受け入れ条件

- frontend は result overlay を待たずに、保護できた言葉と欠けた言葉を表示できる。
- 被弾、復帰、fragment 回収、敵撃破が PresentationRequest と renderState の値で説明できる。
- frontend に mission ID や chunk 本文の直接探索をさせない。

# BE-1-04 background / hazard preset を renderState に解決する

タグ: `[phase:1] [team:backend] [background] [hazard] [contract]`

## 現状確認

- mission や hazard は preset ID を持つが、frontend へ渡る値が弱く、renderer が TS 固定値を使い続けやすい。

## 作業

- battle 開始時に mission の background preset を解決し、`BattleRenderState.background` へ渡す。
- active hazard に visual preset を解決し、`hazard.visual` へ渡す。
- gentle / standard の差分を TypeScript 定数ではなく content preset で表す。
- validator で mission hazard の `visualPresetId` と background preset coverage を確認する。

## 受け入れ条件

- `hazard_magnetic_disaster_gentle` と standard の違いが renderState で確認できる。
- background renderer は `backgroundPresetId` だけでなく density/intensity 系の値を受け取れる。
- missing preset は validation で検出される。

# BE-1-05 renderer ID 分岐禁止の検査を追加する

タグ: `[phase:1] [team:backend] [tooling] [cross-team]`

## 現状確認

- frontend の renderer に `mission:${missionId}:${legacyEntityId}` などの fallback があり、再発防止には source audit が必要。

## 作業

- source audit script に、renderer 配下で `mission:`、`enemyId`、`projectileId` を dispatch key として使っていないかを検査する項目を追加する。
- 例外は migration adapter のファイル名に限定し、通常 renderer では失敗にする。
- FE-1-01 完了後に CI gate とする。

## 受け入れ条件

- 新しい mission / enemy / projectile を追加しても renderer に ID 分岐を足せない。
- migration adapter 以外で legacy ID dispatch が検出された場合、audit が失敗する。
