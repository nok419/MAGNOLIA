# MAGNOLIA playable slice 改修メモ

作成日: 2026-04-28
更新日: 2026-04-28
対象: `mission_good_morning` / `mission_where_are_you` / `mission_evacuation` までの playable slice

## 1. 位置づけ

この文書は、通信体験を強めるための改修依頼を、現在の docs / content / apps の状態に合わせて更新したものです。

以前の記述では、未実装だった字幕欠損表示、scan 入力、探索 signal hint、`mission_evacuation` の本文長について、現状と合わない記述が含まれていました。現在は一部が実装済みです。この文書では「実装済みの入口」と「今後確認・拡張すべき残り」を分けます。

詳細なファイル単位のコードマップは `02_開発体制とディレクトリ構成` を参照してください。この文書では、具体的なファイル名ではなく、contracts、session、persistence、content、Web 表示層の責務で記述します。

## 2. 目的

目的は、敵や弾を増やすことではなく、プレイヤーの行動が「通信の聞き取り」「言葉の欠損」「断片の回収」「信号の探索」に直結していると感じられる playable slice にすることです。

優先する体験は次の 4 点です。

1. ノイズ超過時に、字幕本文を実際に読めなくする。
2. 被弾・聴取失敗後に、欠損した通信断片をその場で回収できるようにする。
3. 探索を「最初から見えているアイコンへ歩く」から「信号を探す」に寄せる。ただし過度に面倒にはしない。
4. ミッションごとに、本文の性質とプレイ内容が一致するよう調整する。

## 4. 非目標

以下は今回の playable slice 調整の範囲に含めません。

- 音声本実装そのもの。
- mission04 以降の追加。
- プレイヤー選択によって通信内容が永久に分岐し、基本本文が回収不能になる構造。
- 何度も同じミッションを周回しないと基本本文が揃わない設計。
- UI 側が content 全量や session 内部状態を直接読んで独自判定する実装。

## 5. 改修 A: ノイズ超過時の字幕欠損

### 現状

聴取不可時の字幕は、`activeSubtitle.audible`、`noiseLevel`、`hearingThreshold`、`reduceFlashing` を入力にして欠損表示へ変換されています。

聴取可能時は通常本文を表示し、聴取不可時は文字化け、伏せ字、黒塗り、グリッチを混ぜて、本文をそのまま読めない状態にします。日本語の文字分割は grapheme 単位を優先し、fallback も持ちます。

### 残り

- 欠損の強さをプレイ感に合わせて調整する。
- 音声実装時に voice mixer、filter、noise SE と同期する。
- `reduceFlashing` 有効時は静的な欠損表示を維持する。
- 聴取不可時の aria-label で完全本文を読ませるかどうかは、アクセシビリティとゲーム上のネタバレ防止の両面から決める。

### 受け入れ条件

- ノイズ超過時に字幕本文が実際に読めない。
- 聴取可能状態に戻ると本文が復帰する。
- `reduceFlashing` 有効時に高速点滅しない。
- 欠損表示は毎フレーム完全ランダムに変わらず、読めないが目にうるさすぎない。

## 6. 改修 B: 欠損フラグメント回収

### 目的

被弾やノイズ超過によって通信が欠損した直後、プレイヤーが能動的に欠損片を回収できるようにします。死亡がないゲームにおける「失敗後の立て直し」を作るための仕組みです。

### 現状

戦闘 renderState には fragment 描画用の ViewModel を受け取る入口があります。Web 表示層は、渡された fragment を画面内に描画できます。

ただし、生成、衝突判定、回収、復元 span への merge、save / archive への統合は、session / persistence 側の責務です。apps / content / docs だけの抽出では full package 側の完成度を断定できないため、今後のリファクタ時に確認対象とします。

### 推奨データ方針

通信本文チャンクは chunk ID を維持し、復元済み範囲は可能なら `chunkId + startRatio/endRatio` の正規化 span として扱います。

```ts
export type TranscriptSpan = {
  chunkId: TranscriptChunkId
  startRatio: number
  endRatio: number
}

export type BattleFragmentViewModel = {
  fragmentId: string
  chunkId: TranscriptChunkId
  startRatio: number
  endRatio: number
  x: number
  y: number
  expiresAtMs: number
  strength: number
}
```

この形式にすると、本文チャンクの `startMs` / `endMs` を軽微に調整しても、chunk ID が維持されていれば復元状態が壊れにくくなります。

### 基本挙動

- ノイズが聴取閾値を超えた時、または被弾により新規欠損が発生した時、戦闘画面内に fragment を生成する。
- fragment は 2.5〜4.0 秒程度で消える。
- 自機が触れると回収され、その時間範囲の通信が部分的に復元される。
- fragment は安全地帯のど真ん中ではなく、少しだけリスクのある位置に出す。
- calm では寿命を長め、terminal では短めにする。

### 受け入れ条件

- 被弾またはノイズ超過後に、画面内へ fragment が出現する。
- fragment を回収すると、該当する通信本文の欠損が部分的に復元される。
- 回収済み範囲は result、archive、save に反映される。
- 本文文字数や chunk の時間を軽微に変更しても、既存復元データが致命的に壊れない。

## 7. 改修 C: 探索 scan pulse と信号探索

### 現状

探索では、scan 入力、signal hints、scan pulses の表示入口があります。scan はキーボード入力と secondary mouse click から送られ、Web 表示層は session から渡された hint / pulse を描画します。

### 方針

アイコンは完全に消さず、段階表示にします。

1. 未発見: 正確なアイコンは出さない。通信強度、波形、視界円の縁の反応だけを出す。
2. 疑似検出: scan や接近で方角・距離帯だけが分かる。ゴースト反応や円弧を出すが、正確な座標アイコンは出さない。
3. 識別済み: 近距離到達または十分な scan で、通常アイコンを出す。以後、map / minimap に残る。
4. 接続済み・完全復元済み: 利便性のため、従来通り常時アイコンを残す。

### 推奨初期値

- 入力: `R` または secondary mouse click。
- 半径: passive leak より広く、遠距離ほど反応と識別進行を減衰させる。
- cooldown: 2.0〜3.0 秒。
- 反応持続: 2.0〜4.0 秒。
- scan で分かる情報: 正確な位置ではなく、方角、距離帯、カテゴリ、信号強度。

### 受け入れ条件

- 未発見通信の正確なアイコンは、最初から常時表示されない。
- scan を使うと、未発見通信の方角・距離帯・カテゴリが分かる。
- scan を使わなくても、近づけば信号の兆候を追える。
- 一度識別した通信・収集物は、map / minimap に残る。
- 初回プレイで次の目的地を見失わない。

## 8. 改修 D: ミッション構成の再調整

### mission_good_morning

目的: 起動シーケンス / 自己診断。

現在の本文は約 55 秒まであり、60 秒ミッションと概ね対応しています。敵配置をだらっと流すより、8〜10 秒単位の機能確認フェーズに分けます。

移動、main、近接、sub、被弾ノイズ、磁気災害、探索開始の順に、本文と wave を対応させます。チュートリアルでは、失敗しても通信が完全に壊れないよう聴取閾値を易しめにします。

### mission_where_are_you

目的: 長すぎない、市民の声の束。

現在の本文は約 85 秒まであり、90 秒ミッションと概ね対応しています。一方で playable slice のテンポとしてはやや長いため、45〜65 秒程度へ圧縮するか、3 人の短い通信束としてテンポを上げるかを検討します。

各 speaker の区間ごとに弾幕の性格を変えます。

- カナ: 細く不安定。回避より聞き取り重視。
- タクミ: 規則的で少し荒い。main で除去しやすい。
- ミサキ: 不安定。hazard と絡める。

最後の「絶対。」は重要フレーズとして、短時間だが強い保護対象にします。

### mission_evacuation

目的: ほとんど壊れた通信の回収。

現在の本文は 55.7 秒まであり、60 秒ミッションの大半が無字幕になる状態ではありません。以前の「0〜8500ms までしか本文がない」という記述は現状と合いません。

今後は、完全な文章を増やすより、短い断片、断続、繰り返し、破損区間を使って「崩壊した公共放送」として調整します。

例:

- 0〜8 秒: 正常な避難放送。
- 10〜20 秒: 繰り返し放送が崩れ始める。
- 22〜35 秒: 断片だけ拾える。
- 38〜50 秒: ほとんど破損。fragment 回収でのみ一部復元。
- 最後: 「自力で……」などの短い残響。

### 受け入れ条件

- 各ミッションの本文タイムラインと mission duration が大きく乖離しない。
- ミッションごとに、本文の性質と敵 / hazard の性質が一致している。
- mission02 が長すぎず、mission03 が空白時間だらけにならない。

## 9. 優先順位

### P0: 現状維持確認と体験穴の修正

- 字幕欠損表示が release build で安定して動くことを確認する。
- `mission_evacuation` の本文タイムラインが現行 content と一致していることを維持する。
- result / archive で、欠損した本文が見える初期対応を確認する。

### P1: playable slice の面白さを上げる

- fragment の生成・回収・復元・save 統合を完成させる。
- scan / passive leak / signal hint の識別進行と永続化を調整する。
- ミッション本文と wave / hazard の対応を改善する。

### P2: 拡張・磨き込み

- normalized transcript span への保存移行。
- 指向性 scan、OS / subsystem による探索性能差。
- 戦闘中の信号帯 / 受信ルート演出。
- ミッション別の演出強化。

## 10. 実装上の注意

- UI は snapshot / renderState / read model だけを見る。
- Web 表示層から content 全量や session 内部へ直接アクセスして、開放条件や秘匿情報を判定しない。
- mission 固有の処理を TypeScript にハードコードしない。mission の違いは content と汎用 schema で表現する。
- 保存データは normalizer を通し、古い save が壊れないようにする。
- 未開放情報の秘匿は維持する。

## 11. 期待する体験

プレイヤーは、ただ敵を倒しているのではなく、通信の言葉を守っていると感じる。

被弾した瞬間、字幕が読めなくなり、失った断片が画面内にこぼれる。プレイヤーは危険を承知で拾いに行くか、次の言葉を守るかを判断する。

探索では、最初から正確な目的地へ一直線に歩くのではなく、強度バー、波形、視界円の反応、scan pulse を頼りに、通信の残響を探す。ただし、一度見つけたものはマップに残り、面倒な再探索は発生しない。

この方向で、MAGNOLIA は普通の STG ではなく、「言葉を欠損させないための STG」「失われた通信を探す探索ゲーム」として立ち上がる。
