# 02_開発体制とディレクトリ構成

更新日: 2026-04-17

## この文書の目的

- 現在の実装で、どこが状態の正本かを明確にします。
- フロントエンド改修時に、どの層まで触ってよいかを固定します。
- Codex と Claude Code が同時に作業しても、ルールと表示がずれない境界を残します。

## 現在の実装方針

- 画面全体は React で構成しています。
- 探索画面と戦闘画面の描画は、現時点では Phaser ではなく Canvas 2D を使っています。
- ゲーム状態の正本は `packages/game-session` です。
- `apps/web` は `game-session` が返す snapshot / renderState を描画する層です。
- 保存は IndexedDB + Dexie です。
- コンテンツの正本は `content/gameplay/*.json` です。
- settings / save slot の既定値と settings 更新規則は `packages/contracts/src/settings.ts` に寄せています。
- save の load / save / import は `packages/persistence/src/save-normalizer.ts` で正規化してから扱います。
- 表示変更と gameplay / save の境界は `08_表示と機能の境界.md` を参照してください。

補足:
- 以前の計画にあった `game-core` `ui-shell` `phaser-client` `content-tools` は、現時点では独立 package として実装していません。
- 今後それらに分割する場合でも、まずは現在の境界を壊さないことを優先します。

## package ごとの責務

### packages/contracts

役割:
- 型の共有
- command / snapshot / renderState の土台
- 空の state や既定値生成の共通化
- content schema 相当の基本形

正本ファイル:
- `packages/contracts/src/game-types.ts`
- `packages/contracts/src/session-types.ts`
- `packages/contracts/src/presentation-types.ts`
- `packages/contracts/src/explore-view.ts`

ここに置くもの:
- ID 型
- master data 型
- save row 型
- `RootSnapshot` `ExploreSnapshot` `BattleSnapshot`
- `GameCommand`
- `PresentationRequest`
- 探索画面と探索履歴で共有する viewport の基準値
- 空の snapshot / access state を安全に組み立てる関数

ここに置かないもの:
- React 用 state
- Canvas 描画関数
- Dexie 実装
- ゲーム進行ロジック

### packages/game-session

役割:
- ゲーム状態の正本
- 探索と戦闘の進行
- 装備解決
- selector による秘匿情報の除去
- renderState の生成

主なファイル:
- `packages/game-session/src/game-session.ts`
- `packages/game-session/src/equipment-runtime.ts`
- `packages/game-session/src/progression.ts`
- `packages/game-session/src/selectors.ts`
- `packages/game-session/src/conditions.ts`
- `packages/game-session/src/hazards.ts`
- `packages/game-session/src/presentation.ts`
- `packages/game-session/src/runtime-types.ts`

責務の分け方:
- `game-session.ts`
  - command 処理
  - stepExplore / stepBattle
  - save 更新
  - mission 開始と終了
- `equipment-runtime.ts`
  - 装備の解決
  - 強化値の適用
  - main / sub / subsystem hook の handler 解決
- `progression.ts`
  - 解析率、復元率、エリア解放率、通信状態の共通計算
  - UI と session で同じ式を使うための pure function
- `selectors.ts`
  - 未開放情報を UI に渡さないための絞り込み
  - feature access
  - archive access
  - map visibility
- `runtime-types.ts`
  - Canvas 描画専用の shape
  - React 側に渡す renderState

### packages/persistence

役割:
- content JSON の読み込み
- content の参照整合チェック
- Dexie による save 実装
- settings と meta の既定値管理

主なファイル:
- `packages/persistence/src/load-content-bundle.ts`
- `packages/persistence/src/dexie/repository.ts`
- `packages/persistence/src/dexie/magnolia-db.ts`
- `packages/persistence/src/defaults.ts`

注意:
- content の import 一覧は `load-content-bundle.ts` に集中しています。
- content を追加した時は、ここへ import と validation の追記が必要です。

### apps/web

役割:
- session とブラウザ入力の接続
- 画面切り替え
- snapshot / renderState の描画
- 純粋な UI レイアウト
- overlay channel の `PresentationRequest` の表示

主なファイル:
- `apps/web/src/app/use-magnolia-app.ts`
- `apps/web/src/app/App.tsx`
- `apps/web/src/app/display-helpers.ts`
- `apps/web/src/app/canvas-markers.ts`
- `apps/web/src/components/PresentationOverlay.tsx`
- `apps/web/src/screens/*`
- `apps/web/src/components/*`
- `apps/web/src/styles/global.css`

責務の分け方:
- `use-magnolia-app.ts`
  - session の初期化
  - input を command / frame input に変換
  - session から snapshot / renderState を取り出して React state へ反映
- `App.tsx`
  - screen ごとの分岐だけ
- `display-helpers.ts`
  - 装備スロット名、日時、経過時間など表示専用の整形
  - screen ごとの文言ずれを避けるための共通関数
- `canvas-markers.ts`
  - transmission / item / minimap marker の見た目定義
  - Explore / Map / MiniMap の見た目変更点を 1 か所へ集約
- `PresentationOverlay.tsx`
  - `channel: "overlay"` の演出表示
  - boot message の入力待ちと reboot / 制限 cue の同期を担当
- `TitleScreen.tsx`
  - タイトルとセーブスロット選択を同一画面で扱います
- `screens/*`
  - 画面単位の UI 合成
- `components/*`
  - Canvas 描画や再利用 UI

## フロントエンド改修の入口

Claude Code が主に触る場所は次です。

- `apps/web/src/screens/*`
- `apps/web/src/components/*`
- `apps/web/src/styles/global.css`

必要に応じて触ってよい場所:
- `apps/web/src/app/App.tsx`
  - 画面の並び替え
  - props の受け渡し整理
- `apps/web/src/hooks/*`
  - キーボード操作の補助

原則として直接触らない場所:
- `packages/game-session/src/game-session.ts`
- `packages/game-session/src/selectors.ts`
- `packages/game-session/src/equipment-runtime.ts`
- `packages/persistence/src/load-content-bundle.ts`

理由:
- ここを UI 都合で触ると、未開放情報の秘匿や save の整合性まで崩れるためです。

## フロントエンド改修ルール

### 1. UI は snapshot / renderState だけを見る

- UI コンポーネントは `content` の全量や save repository を直接参照しません。
- 未開放通信、未探索 node、未取得装備の判定は `game-session` 側で済ませます。
- UI 側で「たぶん見えてよいだろう」と再計算しません。

### 2. 画面遷移は command 経由に限定する

- 新しいボタンを増やす時も、基本は `use-magnolia-app.ts` から `session.dispatch(...)` を呼びます。
- screen を UI 側で直接書き換えません。

### 3. 見た目の都合で必要な値は contract を先に増やす

- たとえばミニマップで別色が必要なら、UI 側で content を漁るのではなく `renderState` に必要な値を増やします。
- 追加順序は `contracts` → `game-session` → `apps/web` です。
- 解析率や通信状態の式を変える時は `packages/game-session/src/progression.ts` を更新し、screen ごとに再実装しません。

### 4. Canvas は描画だけに留める

- `ExploreCanvas.tsx` と `BattleCanvas.tsx` では当たり判定や unlock 判定を持ちません。
- Canvas 内で game rule を増やさないことを徹底します。

### 5. 隠す仕様は UI でも維持する

- 未取得かつ purchase 以外の装備は `???` を維持します。
- 未開放通信の一覧・本文・メタデータは表示しません。
- 表示改善のためでも、この方針を緩めません。

- Canvas の見た目の改善
- タイトル演出
- アーカイブと装備画面の UI

## 追加実装時のルール

### 新しい UI を増やす時

- まず `screen` を増やす必要があるかを判断します。
- 既存 screen 内のタブで済む場合は screen を増やしません。
- 新しい情報が必要なら `renderState` か `snapshot` を増やします。

### 新しい装備を増やす時

- `content/gameplay/equipment/*.json`
- `content/gameplay/equipment/effects/*.json`
- 必要なら `equipment-runtime.ts` の handler registry

の順に追加します。

### 新しい mission を増やす時

- `content/gameplay/missions/*.json`
- `content/gameplay/transmissions/*.json`
- `content/gameplay/transmissions/*.chunks.json`
- 必要なら `areas` `map-logic`
- 最後に `load-content-bundle.ts`

の順に追加します。
