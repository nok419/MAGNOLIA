# 02_開発体制とディレクトリ構成

更新日: 2026-04-28

## この文書の目的

- 現在の実装で、どこが状態の正本かを明確にします。
- フロントエンド改修時に、どの層まで触ってよいかを固定します。
- コードマップに機能の分布をコメントとして残し、古いファイル名を前提に作業しないようにします。

## 現在の実装方針

- 画面全体は React で構成します。
- 探索画面、戦闘画面、マップ画面の描画は Canvas 2D を使います。
- ゲーム状態の正本は `packages/game-session` です。
- `apps/web` は `game-session` が返す snapshot / renderState を描画する層です。
- 保存は IndexedDB + Dexie です。
- コンテンツの正本は `content/gameplay` の JavaScript Object Notation（JSON）です。
- Cascading Style Sheets（CSS）の入口は `apps/web/src/styles/global.css` です。実体は画面・用途ごとの CSS ファイルへ分けます。
- 表示変更と gameplay / save の境界は `docs/08_表示と機能の境界.md` を参照してください。

## 機能分布の要約

| 機能 | 主な場所 | 備考 |
| --- | --- | --- |
| 状態の正本、command 処理、探索・戦闘進行 | `packages/game-session/src/game-session.ts` | User Interface（UI）から直接ルールを再実装しません。 |
| 装備効果、弾、近接、爆発、support field | `packages/game-session/src/battle-effects.ts` / `equipment-runtime.ts` | 戦闘ルールはここで確定します。 |
| 探索 signal、scan、誘導 | `packages/game-session/src/explore-signal-runtime.ts` | UI 側では誘導の見た目だけ扱います。 |
| マップ画面用 view model | `packages/game-session/src/map-view-model.ts` | `MapScreen` が直接 content 全量を探索しないための境界です。 |
| snapshot / renderState 型 | `packages/contracts/src/session-types.ts` / `packages/game-session/src/runtime-types.ts` | UI に渡す情報の形を固定します。 |
| content 読み込みと整合チェック | `packages/persistence/src/load-content-bundle.ts` | content を増やしたらここも更新します。 |
| save 正規化と Dexie repository | `packages/persistence/src/save-normalizer.ts` / `dexie/` | import / load / save の入口です。 |
| Web 側 session 接続 | `apps/web/src/app/internal/` | `useMagnoliaApp` の実装本体です。 |
| 画面合成 | `apps/web/src/screens/` | props で受け取った状態を組み立てます。 |
| Canvas 描画 | `apps/web/src/render/` | 当たり判定や unlock 判定を持ちません。 |
| 再利用 UI と遷移 overlay | `apps/web/src/components/` | `BattleCanvas` は接続、描画本体は `render/battle` です。 |
| design11 表示検証 | `apps/web/src/dev/` / `scripts/design-audit.mjs` | visual fixture と設計監査です。 |

- 型の共有

## 改修時の入口

UI だけを触る場合:
- `apps/web/src/screens/*`
- `apps/web/src/components/*`
- `apps/web/src/render/*`
- `apps/web/src/styles/*`

session と UI の接続を触る場合:
- `apps/web/src/app/internal/use-magnolia-app-impl.ts`
- `apps/web/src/app/internal/magnolia-app-actions.ts`
- `apps/web/src/app/internal/sync-from-session.ts`
- `apps/web/src/app/use-magnolia-input.ts`

gameplay / save / visibility を触る場合:
- `packages/contracts`
- `packages/game-session`
- `packages/persistence`
- `content/gameplay`

原則として、UI 都合だけで直接触らない場所:
- `packages/game-session/src/game-session.ts`
- `packages/game-session/src/selectors.ts`
- `packages/game-session/src/equipment-runtime.ts`
- `packages/persistence/src/load-content-bundle.ts`
- `packages/persistence/src/save-normalizer.ts`

理由:
- ここを UI 都合で触ると、未開放情報の秘匿、装備効果、save の互換性まで影響します。

## フロントエンド改修ルール

### 1. UI は snapshot / renderState だけを見る

- UI コンポーネントは repository を直接参照しません。
- 未開放通信、未探索 node、未取得装備の判定は `game-session` 側で済ませます。
- UI 側で「見えてよいか」を再計算しません。

### 2. 画面遷移は command 経由に限定する

- 新しいボタンを増やす時も、基本は `magnolia-app-actions.ts` から session command を呼びます。
- screen を UI 側の local state だけで書き換えません。

### 3. 見た目の都合で必要な値は contract / renderState を先に増やす

- たとえば Canvas 描画で別の分類が必要なら、UI 側で content を漁るのではなく renderState に必要な値を増やします。
- 追加順序は `contracts` → `game-session` → `apps/web` です。
- 解析率や通信状態の式を変える時は `packages/game-session/src/progression.ts` を更新し、screen ごとに再実装しません。

### 4. Canvas は描画だけに留める

- `render/battle` と `render/explore` では当たり判定や unlock 判定を持ちません。
- Canvas 内で game rule を増やしません。
- 戦闘の当たり判定は `packages/game-session`、見た目は `apps/web/src/render` です。

### 5. 隠す仕様は UI でも維持する

- 未取得かつ purchase 以外の装備は `???` を維持します。
- 未開放通信の一覧・本文・メタデータは表示しません。
- 表示改善のためでも、この方針を緩めません。

## 追加実装時のルール

### 新しい UI を増やす時

- まず `screen` を増やす必要があるかを判断します。
- 既存 screen 内の tab で済む場合は screen を増やしません。
- 新しい情報が必要なら `renderState` か `snapshot` を増やします。

### 新しい装備を増やす時

- `content/gameplay/equipment/*.json`
- `content/gameplay/equipment/effects/*.json`
- 必要なら `equipment-runtime.ts` の handler registry
- 最後に `load-content-bundle.ts`

の順に追加します。

### 新しい mission を増やす時

- `content/gameplay/missions/*.json`
- `content/gameplay/transmissions/*.json`
- `content/gameplay/transmissions/*.chunks.json`
- 必要なら `areas` `map-logic` `visual-presets`
- 最後に `load-content-bundle.ts`

の順に追加します。
