# 02_開発体制とディレクトリ構成

更新日: 2026-05-01

## この文書の目的

- 現在の実装で、どこが状態の正本かを明確にします。
- フロントエンド改修時に、どの層まで触ってよいかを固定します。
- Codex と Claude Code が同時に作業しても、ルールと表示がずれない境界を残します。

## 現在の実装方針

- 画面全体は React で構成しています。
- 探索画面と戦闘画面の描画は、現時点では Phaser ではなく Canvas 2D を使っています。
- ゲーム状態の正本は `packages/game-session` です。
- `apps/web` は `game-session` が返す snapshot / renderState を描画する層です。
- 保存は IndexedDB + Dexie です。
- コンテンツの正本は `content/gameplay/*.json` です。
- settings / save slot の既定値と settings 更新規則は `packages/contracts/src/settings.ts` に寄せています。
- save の load / save / import は `packages/persistence/src/save-normalizer/*` で正規化してから扱います。
- 表示変更と gameplay / save の境界は `08_表示と機能の境界.md` を参照してください。

補足:
- 以前の計画にあった `game-core` `ui-shell` `phaser-client` `content-tools` は、現時点では独立 package として実装していません。
- 今後それらに分割する場合でも、まずは現在の境界を壊さないことを優先します。

## フロントエンド改修の入口

Claude Code が主に触る場所は次です。

- `apps/web/src/screens/*`
- `apps/web/src/components/*`
- `apps/web/src/styles/global.css`
  - 実体 CSS は `apps/web/src/styles/*.css` に分かれています

必要に応じて触ってよい場所:
- `apps/web/src/app/App.tsx`
  - 画面の並び替え
  - props の受け渡し整理
- `apps/web/src/hooks/*`
  - メニューなど画面 UI の補助

原則として直接触らない場所:
- `packages/game-session/src/game-session.ts`
- `packages/game-session/src/selectors.ts`
- `packages/game-session/src/equipment-runtime.ts`
- `packages/persistence/src/load-content-bundle.ts`

理由:
- ここを UI 都合で触ると、未開放情報の秘匿や save の整合性まで崩れるためです。

## フロントエンド改修ルール

### 1. UI は snapshot / renderState だけを見る

- UI コンポーネントは `content` の全量や save repository を直接参照しません。
- 未開放通信、未探索 node、未取得装備の判定は `game-session` 側で済ませます。
- UI 側で「たぶん見えてよいだろう」と再計算しません。

### 2. 画面遷移は command 経由に限定する

- 新しいボタンを増やす時も、基本は `magnolia-actions.ts` で command を作り、`session-command-runner.ts` 経由で dispatch と state sync を行います。
- screen を UI 側で直接書き換えません。

### 3. 見た目の都合で必要な値は contract を先に増やす

- たとえばミニマップで別色が必要なら、UI 側で content を漁るのではなく `renderState` に必要な値を増やします。
- 追加順序は `contracts` → `game-session` → `apps/web` です。
- 解析率や通信状態の式を変える時は `packages/game-session/src/progression.ts` を更新し、screen ごとに再実装しません。

### 4. Canvas は描画だけに留める

- `ExploreCanvas.tsx` と `BattleCanvas.tsx` では当たり判定や unlock 判定を持ちません。
- Canvas 内で game rule を増やさないことを徹底します。

### 5. 隠す仕様は UI でも維持する

- 未取得かつ purchase 以外の装備は `???` を維持します。
- 未開放通信の一覧・本文・メタデータは表示しません。
- 表示改善のためでも、この方針を緩めません。

## 追加実装時のルール

### 新しい UI を増やす時

- まず `screen` を増やす必要があるかを判断します。
- 既存 screen 内のタブで済む場合は screen を増やしません。
- 新しい情報が必要なら `renderState` か `snapshot` を増やします。

### 新しい装備を増やす時

- `content/gameplay/equipment/*.json`
- `content/gameplay/equipment/effects/*.json`
- 必要なら `equipment-runtime.ts` の handler registry

の順に追加します。

### 新しい mission を増やす時

- `content/gameplay/missions/*.json`
- 必要なら `content/gameplay/battle-spawn-points/*.json`
- 必要なら `content/gameplay/movement-patterns/*.json`
- `content/gameplay/transmissions/*.json`
- `content/gameplay/transmissions/*.chunks.json`
- 必要なら `areas` `map-logic`
- 最後に `npm run content:manifest` と `npm run content:validate`

の順に追加します。
