# 07_スライス定義

更新日: 2026-04-29

## この文書の目的

- 現在の playable slice を固定します。
- 実装・調整・ドキュメント更新の対象範囲を明確にします。

## 現在のスライス範囲

- タイトル
- セーブスロット選択
- チュートリアル探索
- mission01 `mission_good_morning`
- mission02 `mission_where_are_you`
- mission03 `mission_evacuation`
- mission03 クリア後に探索へ戻るところまで

## 進行順

1. 新規開始
2. チュートリアル区域で `tx_good_morning` に接続
3. `mission_good_morning` をクリアして `eq_os_magnolia` を取得
4. OS を換装して探索制限を解除
5. `tx_where_are_you` と `tx_evacuation` を同時に開放する
6. `mission_where_are_you` と `mission_evacuation` は順不同で挑戦できる

## このスライスで保証すること

- 3 つのミッションは連続した進行条件で開放されること
- settings / save / archive / equipment が現在実装に追従していること
- Dexie 保存データは load / save / import の入口で正規化されること
- mission03 は 55.7 秒まで避難放送チャンクを持ち、60 秒ミッションの大半が無字幕にならないこと
- mission02 は 65 秒程度の本文へ圧縮し、3 人の声を長い周回ではなく短い通信束として聞けること
- 探索では未識別通信の正確な座標をすぐ出さず、信号ヒントと scan によって識別へ進めること
- 重要フレーズは `TranscriptChunk.importance` で示し、断片回収の猶予やリザルト抜粋の優先度へ反映されること

## Content 改修の現行判断

- `mission_good_morning` は自己診断の通信として扱い、操作説明も「ノイズ源を弱める」「聴取の余白を作る」方向に寄せる
- `mission_where_are_you` は 3 人の短い通信束とし、最後の「絶対。」を `critical` chunk として扱う
- `mission_evacuation` は壊れた公共放送として、終盤の断片を `critical` chunk として扱う
- 装備説明はダメージ量の比較ではなく、可視ノイズの抑制、聴取余白、欠損防止を基準に書く
- リザルトは本文復元、回収した断片、重要フレーズ保持、初開示メタ情報を表示し、アーカイブは重要 chunk を強調する

## このスライスで扱わないこと

- mission04 以降
- クラウド同期
- content-tools による自動 bundle 生成
- キーコンフィグ UI の本実装
