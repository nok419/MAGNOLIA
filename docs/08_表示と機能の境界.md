# 08_表示と機能の境界

更新日: 2026-04-29

## この文書の目的

- フロントエンドチームとアート&デザインチームが、見た目や演出を変えても機能を壊しにくい境界を明示します。
- mission ごとの演出調整を、独自関数ではなく content と renderState の範囲で進める前提を固定します。

## 正本

- gameplay の正本
  - `packages/game-session`
- save / settings / import-export の正本
  - `packages/persistence`
- 表示の正本
  - `apps/web`
- 描画に渡してよい値の正本
  - `packages/game-session/src/runtime-types.ts`

## 見た目側が安全に変更できる場所

- `apps/web/src/components/*`
- `apps/web/src/screens/*`
- `apps/web/src/styles/global.css`
- `apps/web/src/app/canvas-markers.ts`
- `content/gameplay/missions/*.json`
  - 敵出現時刻
  - 敵編成
  - generic override
  - hazard の位置、時間、移動
  - 欠損フラグメントの寿命、発生間隔、復元幅
- `content/gameplay/transmissions/*.chunks.json`
  - 本文の時間範囲
  - 重要フレーズの指定
  - chunk 単位の fragment 回収補正
- `content/gameplay/map-logic/*.json`
  - 探索 node の座標
  - 信号反応の距離、識別進行、表示強度の補正
- `content/gameplay/enemies/*.json`
  - HP、挙動種別、弾パターン参照
- `content/gameplay/bullet-patterns/*.json`
  - cadence、burst、rotation
- `content/gameplay/projectiles/*.json`
  - speed、noiseDamage、見た目 preset

## 直接触らない前提の場所

- `apps/web` から repository を直接読む変更
- `apps/web` から session 内部状態へ直接触る変更
- 画面側で missionId を見て独自にゲームルールを分岐する変更
- mission ごとに TypeScript 側へ専用関数を足して敵配置や弾幕を定義する変更

## 拡張手順

1. 見た目だけで足りる場合
   - `apps/web` の component / style を変更します。
2. 表示に必要な値が足りない場合
   - `runtime-types.ts` に renderState を追加します。
   - `game-session.ts` で renderState を組み立てます。
   - snapshot の組み立てだけで済む場合は `session-snapshots.ts` を更新します。
   - UI はその追加フィールドだけを読みます。
3. gameplay 調整の場合
   - まず `content/gameplay/*.json` で表現できるか確認します。
   - 既存の generic schema に入らない場合だけ、contracts → loader validation → session の順で拡張します。

## 敵配置と弾幕のルール

- mission の違いは、基本的に `waves` と `hazards` の差分で表現します。
- 敵の細かな差分は `EnemySpawn.overrides` の許可済みキーだけで表現します。
- 現在 loader が許可している override は次です。
  - `speed`
  - `driftX`
  - `wobbleAmplitude`
  - `wobblePeriodMs`
  - `pauseAtY`
  - `pauseMs`
- 新しい表現が必要なら、まず generic なキーとして追加し、特定 mission 専用の処理は避けます。

## ミッション体験の設計原則

- 敵は「人間を攻撃する意思を持つ機体」ではなく、空間に残ったノイズ源として扱います。
- 敵弾は自機を狙う攻撃ではなく、通信を乱す無差別な可視ノイズとして設計します。
- 敵の移動は、ふらつきや追尾で難しくするのではなく、弾幕の形、密度、出現間隔、画面内の余白で緊張を作ります。
- ノイズ源の消散は通信を乱す要因を減らす行為として見せます。消散時は解析率、ノイズ軽減、視覚的な消散を結びつけます。
- 新しい敵や弾幕を追加する場合、まず `content/gameplay/missions/*.json`、`content/gameplay/enemies/*.json`、`content/gameplay/bullet-patterns/*.json`、`content/gameplay/projectiles/*.json` で表現します。
- content だけで表現できない挙動は、contracts、loader validation、session runtime、renderState の順で拡張します。TypeScript 側に mission 固有の例外処理を増やしません。
- 欠損フラグメントは `MissionMaster.fragmentRecovery` と `TranscriptChunk.importance` / `fragmentRecovery` で調整します。Web は fragment の raw content を読まず、`BattleRenderState.fragments` と `TranscriptViewChunk` を表示します。
- 探索信号は `WorldMapLogic` の `signalProfile` を session が解決し、`ExploreSignalHintViewModel` と `ExploreScanPulseViewModel` として渡します。scan pulse の表示半径は、現在反応しうる node の `signalProfile.scanRadius` の最大値を使います。Web は mission ID や transmission ID を見て信号表示を分岐しません。

## save と UI の注意

- settings 変更は `changeSetting` command 経由でのみ行います。
- 装備購入、強化、装着、アーカイブ選択、mission 開始は session 側で検証します。
- App は `apps/web/src/app/app-commands.ts` の command table から session command を呼びます。成功可否、報酬付与、探索 collectible の domain event は session 側で確定し、App は `drainDomainEvents()` の結果を popup や modal 表示へ変換します。
- `seenEquipment` と scan hint の dismissal は User Interface（UI） preference として browser storage に残します。save 内の content 識別子は `content/gameplay/migrated-id-map.json` を loader と save normalizer の両方で使って変換します。
- 探索画面の装備誘導は `selectEquipmentHint()` が `rewardEquipmentIds` と装備済み状態から判定します。App hook に mission や equipment の固定識別子による分岐を戻しません。
- `saveToSlot` は「別スロットへ複製して保存」です。現在操作中のスロットは切り替えません。

## 現行の画面・描画境界

- `MenuScreen.tsx` は tab と画面合成だけを持ちます。
- 装備、アーカイブ、設定の各表示は `apps/web/src/screens/menu/*Panel.tsx` に置きます。
- `BattleCanvas.tsx` は canvas 要素の初期化だけを持ちます。
- 戦闘の描画順、描画 registry、個別の描画関数は `apps/web/src/components/battle-renderer.ts` に置きます。
- `PresentationRequest` は overlay だけに限定しません。`battle.player.hit`、`battle.noise.peak`、`battle.noise.clear`、`battle.invincible.start` などは App が `activeNonOverlayPresentations` に保持し、`BattleCanvas` へ渡します。
- `reduceFlashing` が有効な場合も、PresentationRequest の意味は消しません。強い点滅ではなく、枠線、リング、薄いノイズ層などで状態を残します。
- 戦闘の effect 適用、弾生成、弾移動、爆発処理は `packages/game-session/src/battle-effects.ts` に置きます。
- CSS の入口は `apps/web/src/styles/global.css` です。実装は画面単位の CSS ファイルへ分け、変更対象の画面に対応するファイルを編集します。

## screen props 置換状況

1. `MapScreen.tsx` は `ContentBundle` 全体ではなく、session selector が返す `WorldMapViewModel` と callback だけを受け取ります。mapId、表示済み node、area bounds、metadata unlock 済みの通信情報は selector 側で確定します。
2. `BattleScreen.tsx` は報酬装備名、slot label、result transcript preview、mission progress を `BattleResultViewModel` として受け取ります。戦闘結果表示のために content 全体を読みません。
3. 探索中の click / scan / interact の対象判定は `ExploreInteractionTargets` として session selector に定義します。画面側で content の raw node を読んで gameplay 判定しない方針を維持します。
4. 装備誘導は現在の `selectEquipmentHint()` を正本とします。今後、装備 modal や menu panel が同じ判定を必要とする場合も、画面側で mission / equipment 識別子を直接比較しません。
