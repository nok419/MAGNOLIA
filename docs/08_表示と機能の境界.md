# 08_表示と機能の境界

更新日: 2026-04-30

## この文書の目的

この文書は、見た目や演出を変更してもゲームルール、保存状態、未開放情報を壊さないための境界を定義します。

詳細なファイル単位のコードマップは `02_開発体制とディレクトリ構成` を正本にします。この文書では、原則としてファイル名ではなく、層と責務で記述します。

## 正本

- gameplay の正本は session 層です。
- save、settings、import / export の正本は persistence 層です。
- content の正本は gameplay content です。
- 表示の正本は Web 表示層です。
- 画面と renderer に渡してよい gameplay 情報の正本は、session が公開する snapshot / renderState です。

## 基本ルール

表示層は、ゲームの正しさを判断しません。

表示層が行ってよいことは、公開済みの snapshot / renderState / ViewModel を読んで、見た目、配置、補助テキスト、演出強度へ変換することです。

表示層が行ってはいけないことは、content 全量、保存データ、session 内部状態を直接読んで、開放条件、衝突判定、報酬、解析率、復元率、聴取可否を独自に決めることです。

## 現行実装での移行中の例外

現行 Web には、app shell が content、repository、session を接続する composition root として働いている箇所があります。これは起動時の依存注入として許容します。

menu、equipment、archive、map は ViewModel / renderState 入力へ移行済みです。装備名、価格、強化可否、未取得 masking、アーカイブ本文、metadata unlock、map marker は session の selector が作った表示値を使います。

今後の CRUD 確保と SOLID 最適化でも、画面へ渡す値は selector / read model / renderState に寄せ、画面が content 全量から自分で表示可否を推測する構造を戻しません。

## 見た目側が安全に変更できる範囲

安全に変更できるのは、画面構成、CSS、Canvas 描画、アイコン、色、アニメーション、字幕の欠損表現、scan pulse や signal hint の見せ方、battle fragment の見せ方です。

ただし、次の条件を守ります。

- gameplay 判定を描画側へ追加しない。
- mission ID を見て表示層で専用ルールを分岐しない。
- 未発見ノード、未開放本文、未獲得装備を、表示層が content から掘り起こして出さない。
- collision、damage、analysis、restoration、reward、unlock は session 側の結果だけを見る。

## content で調整できる範囲

ミッション体験の差分は、まず gameplay content で表現します。

- mission: 敵出現時刻、敵編成、spawn override、hazard の位置・時間・移動、報酬、危険度。
- enemy: HP、挙動種別、解析貢献、弾幕参照。
- bullet pattern: 発射間隔、弾数、角度、回転。
- projectile: 速度、寿命、ノイズダメージ、見た目 preset。
- transmission / chunks: 通信本文、speaker、時刻範囲、カテゴリ。
- map logic: area、transmission、warp、collectible のノード配置と条件。
- equipment / effects: 装備名、slot、強化段階、handler ID、効果パラメータ。
- progression conditions: 開放条件。
- visual presets: enemy、projectile、hazard の rendererKind、projectile bodyKind、paletteRole、演出補助値。
- hitbox presets: player、enemy、projectile の判定形状と寸法。
- background presets: mission 背景の theme、密度、scanline、vignette。
- presentation cues: overlay、explore、battle、transition、UI の cue と reduceFlashingVariant。

visual preset、hitbox preset、background preset、presentation cue は現行 content の正本です。接続順は、content schema、loader validation、session、renderer、validator です。表示層は ID を見て mission / enemy / projectile ごとの個別分岐を増やさず、renderState と preset から渡された公開フィールドだけを使います。

missing preset、未対応 rendererKind、必須 paletteRole 欠落は loader または `npm run content:validate` で失敗させます。battle renderer の ID dispatch 回帰は `npm run source:audit` で検出します。例外を置く場合は migration adapter としてファイル名で分離し、通常 renderer には置きません。

## 拡張手順

見た目だけで足りる場合は、Web 表示層の component、style、Canvas renderer を変更します。

表示に必要な値が足りない場合は、contracts の公開型、session の snapshot / renderState 生成、必要な selector を先に拡張します。UI は追加された公開フィールドだけを読みます。

gameplay 調整の場合は、まず gameplay content の既存 schema で表現できるか確認します。既存 schema に入らない場合だけ、contracts、loader validation、session、表示層の順で拡張します。

新規 enemy visual、projectile visual、hazard visual、background preset を追加する手順は次です。

1. `content/gameplay/visual-presets`、`hitbox-presets`、`background-presets`、または `presentation-cues.json` に JSON を追加する。
2. 参照元の enemy、projectile、mission、hazard、cue へ ID を設定する。
3. `npm run content:manifest` で generated manifest を更新する。
4. 必要なら `packages/contracts/src/game-types.ts` と `packages/contracts/src/content-kinds.ts` の型・許可値を更新する。
5. `tools/content-validator/src/*` の検証を同じ許可値に合わせる。
6. `packages/game-session` で renderState / ViewModel に必要な値を公開する。
7. Web renderer は公開値だけを消費し、content 全量や mission ID から表示可否を再判定しない。

## 敵配置と弾幕のルール

mission の違いは、基本的に `waves` と `hazards` の差分で表現します。

敵の細かな差分は `EnemySpawn.overrides` の許可済みキーだけで表現します。現行 content で使う override は次の範囲です。

- `speed`
- `driftX`
- `wobbleAmplitude`
- `wobblePeriodMs`
- `pauseAtY`
- `pauseMs`

新しい表現が必要なら、特定 mission 専用の TypeScript 分岐ではなく、汎用キーとして追加します。

## 探索表示の境界

探索では、未識別通信の正確な座標を最初から表示しません。

表示層は、session から渡される `signalHints`、`scanPulses`、visible node、現在エリア名、通信強度などを描画します。未識別ノードの正確な位置を content から逆引きして描画してはいけません。

scan 入力、passive leak、識別済み判定、map / minimap に残すかどうかは session 側の責務です。描画側は結果だけを見ます。

menu / equipment / archive でも同じです。表示層は `EquipmentCatalogViewModel`、`ArchiveViewModel`、`MenuViewModel` を表示し、価格、強化可否、未取得 masking、archive 本文の秘匿を content や profile から再計算しません。

## 戦闘表示の境界

戦闘では、敵、弾、hazard、pickup、barrier、support field、battle fragment、字幕状態を renderState から描画します。

`BattleRenderState` は `background`、敵・弾の `visual` / `hitbox`、hazard の `visual` を解決済み preset として持ちます。renderer は `backgroundPresetId`、`enemyId`、`projectileId`、`missionId` を dispatch key にせず、preset の `rendererKind`、projectile の `bodyKind`、`paletteRole`、`trailKind`、`glowIntensity`、background の density / intensity 系の値を読む前提です。

戦闘通信 UI は result overlay を待たず、`currentChunkId`、`currentChunkProtectedRatio`、`newlyLostRange`、`newlyRecoveredRange`、`noiseLevel`、`hearingThreshold`、`analysisRate` を読みます。`battle.subtitle.damage` は欠損範囲、`battle.fragment.recovered` は回収範囲、`battle.noiseSource.clear` は敵撃破によるノイズ源除去を示す cue です。`battle.mission.beat` は mission beat と本文 chunk の対応を示します。

通信音声は `BattleRenderState.transmissionAudio` を使って web audio 側で同期します。session は `audioPlaybackMs` という仮想時計を正本として公開し、Web 側の `AudioHub` は実音声の位置がずれた時だけ seek します。音声なし通信では `audioAssetId` が未設定のため、従来どおり仮想時計と字幕だけが進みます。

表示層は次を行いません。

- 敵弾や hazard の当たり判定。
- ノイズダメージの加算。
- 解析率、復元率、報酬の計算。
- フラグメント回収判定。
- 聴取可否の判定。
- 音声の進行を正本として字幕時刻を書き換えること。

字幕の欠損表示は UI 側で行ってよい見た目変換です。ただし、`activeSubtitle.audible`、`noiseLevel`、`hearingThreshold` など session が公開した値だけを入力にします。

battle fragment の描画も UI 側の責務です。ただし、生成、寿命、回収、復元 span への反映、save 統合は session / persistence 側の責務です。

## save と UI の注意

settings 変更は command 経由でのみ行います。

装備購入、強化、装着、アーカイブ選択、mission 開始、warp、探索ノード interaction は session 側で検証します。

`saveToSlot` は「別スロットへ複製して保存」です。現在操作中のスロットを切り替える操作ではありません。

保存データは normalizer を通し、古い save が壊れないようにします。画面側が保存形式を直接解釈して分岐しないでください。

## ミッション体験の設計原則

敵は「人間を攻撃する意思を持つ機体」ではなく、空間に残ったノイズ源として扱います。

敵弾は自機を狙う攻撃ではなく、通信を乱す無差別な可視ノイズとして設計します。

敵の移動は、ふらつきや追尾だけで難しくするのではなく、弾幕の形、密度、出現間隔、画面内の余白で緊張を作ります。

敵撃破はノイズ源を減らす行為として見せます。撃破時は解析率、ノイズ軽減、視覚的な消散を結びつけます。

新しい敵や弾幕を追加する場合は、まず content と汎用 schema で表現します。TypeScript 側に mission 固有の例外処理を増やしません。
